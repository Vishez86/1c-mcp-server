# 1C Query Language — справочник

Полная справочная база по языку запросов 1С:Предприятия 8.

**Источники:**
- Официальная документация ИТС, «Глава 8. Работа с запросами» (платформа 8.3.37) — высший приоритет по синтаксису и механике языка.
- Е.Ю. Хрусталёва «Язык запросов 1С:Предприятия 8» — методика и оптимизация.
- Скриншоты конфигуратора БП КОРП — высший приоритет по составу полей виртуальных таблиц конкретной конфигурации (официальная глава 8 их не перечисляет).

Подробная версия, provenance и правила разрешения конфликтов источников: `references/version-provenance.md`.

## Правила использования

1. **Перед написанием запроса** — получи релевантные секции через MCP documentation tools; локальные `references/*.md` читай только как fallback
2. **Параметры виртуальных таблиц** — всегда явно, даже если пустые (через запятую)
3. **Поля виртуальных таблиц** — сверяй имена по справочнику, не угадывай
4. **Данные только из инструментов** — никогда не заполнять результаты из памяти

## MCP retrieval

Если в текущем 1С MCP доступны tools документации, не читай большие reference-файлы целиком.

Порядок:
1. Если нужно понять доступные разделы, вызови `list_1c_language_doc_topics`
2. Для точечных вопросов вызови `search_1c_language_docs` с `version="8.3.37"`
3. Если нужен полный фрагмент, вызови `read_1c_language_doc_section`
4. При сомнении в версии или источнике вызови `get_1c_language_doc_provenance`
5. Для фактических полей конкретной базы используй 1С metadata/data tools, а не справочник

Если documentation tools недоступны, используй локальный fallback: читай `references/*.md` напрямую по таблице структуры справочника.

## Быстрая справка: критичные ограничения

### Синтаксис верхнего уровня
- Порядок слов в ВЫБРАТЬ строго фиксирован: `ВЫБРАТЬ [РАЗРЕШЕННЫЕ] [РАЗЛИЧНЫЕ] [ПЕРВЫЕ N]`. `ПЕРВЫЕ` идёт **после** `РАЗЛИЧНЫЕ`, иначе синтаксическая ошибка.
- `ВЫБОР … КОГДА … ТОГДА … ИНАЧЕ … КОНЕЦ` — см. `query-syntax.md#выбор-case`. `ВЫБОР` **нельзя** вложить в агрегатную функцию.
- Приоритет логических операторов: `НЕ` > `И` > `ИЛИ`. В сложных условиях ставь скобки.

### NULL
- Любое сравнение с участием `NULL` даёт `NULL`; в условии (`ГДЕ`/`ПО`/`КОГДА`) `NULL` трактуется как **ложь**.
- Сравнение строк в запросе **игнорирует концевые пробелы** (в отличие от встроенного языка).
- Замена `NULL` — `ЕСТЬNULL(Поле, 0)`; проверка — `Поле ЕСТЬ NULL` / `Поле ЕСТЬ НЕ NULL`.

### РегистрБухгалтерии
- `Остатки` — только **один параметр** `Период` (не НачДата/КонДата)
- `ОборотыДтКт` — **нет** `КоличествоОборот`, только `КоличествоОборотДт`/`КоличествоОборотКт`
- `ОстаткиИОбороты` — **нет** `УсловиеКорСчета`/`КорСубконто`

### РегистрНакопления
- `Остатки` — суффикс ресурсов: `КоличествоОстаток` (не `Количество`)
- `Обороты` — суффикс ресурсов: `КоличествоОборот`, `КоличествоПриход`, `КоличествоРасход`
- `ОстаткиИОбороты` — суффиксы: `КоличествоНачальныйОстаток`, `КоличествоКонечныйОстаток`
- `ВидДвижения` — только у регистров **остатков**; у оборотных нет

### РегистрСведений
- `ГДЕ Цена >= 300` vs `.СрезПоследних(, Цена >= 300)` — **разный результат!**
- Условие в параметре ВТ фильтрует **до** построения среза; `ГДЕ` — **после**

### ПланСчетов
- Фильтровать **по ссылке**, не по коду — `Ссылка = ЗНАЧЕНИЕ(ПланСчетов.Хозрасчетный.РасчетыСПоставщиками)`
- Иерархия счетов — по полю `Родитель`, не по коду

### Прочее
- `limit` в `get_accounting_accounts_map` — **не более 999** (ошибка парсера)
- `СГРУППИРОВАТЬ ПО` — имена полей, **не псевдонимы**
- `УПОРЯДОЧИТЬ ПО` — **обязателен** в любом рабочем запросе
- `РАЗНОСТЬДАТ` — считает **календарную** разницу (не банковские/рабочие дни); запрещена в параметре `Период` виртуальной таблицы
- `АБС` — **функции нет** в языке запросов 1С. Замена: `ВЫБОР КОГДА X < 0 ТОГДА -X ИНАЧЕ X КОНЕЦ`. В `ИМЕЮЩИЕ` вместо `АБС(агрегат) > N` — два условия: `агрегат > N ИЛИ агрегат < -N`
