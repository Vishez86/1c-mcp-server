## Структура запроса

Запрос состоит из секций. Обязательна только первая — описание запроса.

```
// Секция 1: Описание запроса (обязательно)
ВЫБРАТЬ [РАЗРЕШЕННЫЕ] [РАЗЛИЧНЫЕ] [ПЕРВЫЕ N]
    <поля выборки>
[ПОМЕСТИТЬ <ВременнаяТаблица> | ДОБАВИТЬ <ВременнаяТаблица>]
ИЗ
    <таблицы и соединения>
[ИНДЕКСИРОВАТЬ ПО [НАБОРАМ] <поля>]
[ГДЕ <условие>]
[СГРУППИРОВАТЬ ПО <поля> | СГРУППИРОВАТЬ ПО ГРУППИРУЮЩИМ НАБОРАМ (...)]
[ИМЕЮЩИЕ <условие на агрегаты>]
[ДЛЯ ИЗМЕНЕНИЯ <таблицы верхнего уровня>]

// Секция 2: Объединение (необязательно)
[ОБЪЕДИНИТЬ [ВСЕ]
ВЫБРАТЬ ...]

// Секция 3: Упорядочивание (необязательно)
[УПОРЯДОЧИТЬ ПО <поля>]
[АВТОУПОРЯДОЧИВАНИЕ]

// Секция 4: Итоги (необязательно)
[ИТОГИ <агрегаты> ПО <поля>]
```

> **Порядок слов после ВЫБРАТЬ фиксирован:** `РАЗРЕШЕННЫЕ` → `РАЗЛИЧНЫЕ` → `ПЕРВЫЕ N`. Например, `ВЫБРАТЬ ПЕРВЫЕ 5 РАЗЛИЧНЫЕ` — ошибка; правильно `ВЫБРАТЬ РАЗЛИЧНЫЕ ПЕРВЫЕ 5`.
>
> `РАЗРЕШЕННЫЕ` — запрос выберет только записи, на которые у текущего пользователя есть права (актуально при наложенных ограничениях доступа RLS). Без него запрос упадёт на записи, к которым нет доступа.
>
> Ключевые слова имеют русский и английский вариант написания (SELECT = ВЫБРАТЬ, FROM = ИЗ, WHERE = ГДЕ и т.д.). Регистр букв значения не имеет.

## ВЫБРАТЬ — список полей

```sql
-- Все поля таблицы
ВЫБРАТЬ *
ИЗ Справочник.Товары

-- Конкретные поля
ВЫБРАТЬ
    Товары.Код,
    Товары.Наименование,
    Товары.Цена
ИЗ Справочник.Товары КАК Товары

-- Псевдонимы полей
ВЫБРАТЬ
    Товары.Наименование КАК Название,
    Товары.Цена КАК СтоимостьЗакупки
ИЗ Справочник.Товары КАК Товары

-- ПЕРВЫЕ N — ограничение количества записей
ВЫБРАТЬ ПЕРВЫЕ 10
    Товары.Наименование
ИЗ Справочник.Товары КАК Товары
УПОРЯДОЧИТЬ ПО Товары.Цена УБЫВ

-- РАЗЛИЧНЫЕ — уникальные строки (убирает дубли)
ВЫБРАТЬ РАЗЛИЧНЫЕ
    Накладная.Покупатель
ИЗ Документ.РасходнаяНакладная КАК Накладная
```

> **Правило:** псевдонимы полей выборки рекомендуется всегда задавать явно — это защищает алгоритм обработки результата от поломки при переименовании полей.
>
> При указании `*` в результат **не** включаются виртуальные поля исходных таблиц (например, поля представлений).

## ИЗ — источники данных

Имена таблиц формируются по принципу: `<КлассОбъектов>.<ИмяОбъекта>`.

```sql
-- Реальные таблицы
ИЗ Справочник.Контрагенты
ИЗ Документ.РеализацияТоваровУслуг
ИЗ РегистрСведений.Цены
ИЗ РегистрНакопления.Продажи
ИЗ РегистрБухгалтерии.Хозрасчетный

-- Табличная часть документа
ИЗ Документ.РасходнаяНакладная.Состав КАК Состав

-- Виртуальные таблицы (параметры — в скобках)
ИЗ РегистрСведений.Цены.СрезПоследних(&Дата, Товар = &Товар)
ИЗ РегистрНакопления.Продажи.Остатки(&Дата, )
ИЗ РегистрНакопления.Продажи.Обороты(&НачДата, &КонДата, , )
ИЗ РегистрБухгалтерии.Хозрасчетный.ОстаткиИОбороты(&Нач, &Кон, , , )
```

> Параметры виртуальных таблиц **всегда указывать явно** — это ключевое правило оптимизации (см. Хрусталёва, Глава 4).
>
> Предложение `ИЗ` можно опустить, только если источники полностью квалифицированы в списке полей выборки.

## ГДЕ — условия отбора

```sql
ГДЕ Накладная.Дата >= &НачалоПериода
  И Накладная.Дата <= &КонецПериода

-- Несколько условий
ГДЕ Товар.Цена > 1000
  И Товар.Наименование ПОДОБНО "%Иван%"

-- Условие на NULL
ГДЕ Цены.Цена ЕСТЬ NULL
ГДЕ Цены.Цена ЕСТЬ НЕ NULL

-- Проверка типа
ГДЕ ТИПЗНАЧЕНИЯ(Субконто1) = ТИП(Справочник.Контрагенты)
```

> **Важно:** поле в `ГДЕ` не обязано быть в списке `ВЫБРАТЬ`. Но арифметические операции и функции от полей в основном условии `ГДЕ` отключают использование индексов.

## Операторы условий

| Оператор | Описание | Пример |
|----------|----------|--------|
| `=`, `<>`, `<`, `>`, `<=`, `>=` | Сравнение | `Цена > 0` |
| `И`, `ИЛИ`, `НЕ` | Логические | `НЕ Проведен` |
| `МЕЖДУ ... И ...` | Диапазон (включительно) | `Дата МЕЖДУ ДАТАВРЕМЯ(2024,1,1) И ДАТАВРЕМЯ(2024,12,31)` |
| `В (...)` | Вхождение в список | `Статус В (&Список)` |
| `НЕ В (...)` | Не в списке | `Счет НЕ В (&Исключения)` |
| `В ИЕРАРХИИ (...)` | Принадлежность иерархии | `Ссылка В ИЕРАРХИИ (&Группа)` |
| `ПОДОБНО "шаблон"` | Шаблон строки | `Наименование ПОДОБНО "%ООО%"` |
| `НЕ ПОДОБНО` | Не совпадает с шаблоном | |
| `ЕСТЬ NULL` | Проверка на NULL | `Цена ЕСТЬ NULL` |
| `ЕСТЬ НЕ NULL` | Не NULL | |
| `ССЫЛКА <Тип>` | Проверка типа ссылки | `Рег ССЫЛКА Документ.Реализация` |

### Шаблоны ПОДОБНО

| Символ | Значение |
|--------|----------|
| `%` | Любое количество любых символов |
| `_` | Один любой символ |
| `[abc]` | Один из символов a, b, c |
| `[^abc]` | Любой символ кроме a, b, c |
| `[а-я]` | Символ из диапазона |

```sql
-- С параметром (рекомендуется)
ГДЕ Наименование ПОДОБНО "%" + &ЧастьНаименования + "%"
```

### СПЕЦСИМВОЛ — экранирование служебных символов

Чтобы искать литеральные `%`, `_`, `[`, `]`, `^`, задаётся символ экранирования через `СПЕЦСИМВОЛ`. Символ, стоящий после него в шаблоне, теряет служебный смысл.

```sql
-- Найти строки, содержащие литеральный символ подчёркивания "_":
ГДЕ Поле ПОДОБНО "%!_%" СПЕЦСИМВОЛ "!"

-- Найти строки, содержащие литеральный "%":
ГДЕ Поле ПОДОБНО "%!%%" СПЕЦСИМВОЛ "!"
```

> В клиент-серверном варианте слишком длинный шаблон `ПОДОБНО` может не выполниться (зависит от СУБД).

### Оператор В по нескольким полям

```sql
-- С вложенным запросом
ГДЕ (Состав.Номенклатура, Состав.Характеристика) В
        (ВЫБРАТЬ
            Допустимые.Номенклатура,
            Допустимые.Характеристика
        ИЗ
            РегистрСведений.ДопустимыеХарактеристики КАК Допустимые)

-- С таблицей значений (используются первые N колонок ТЗ)
ГДЕ (Состав.Номенклатура, Состав.Характеристика) В (&ТаблицаЗначений)
```

> Из вложенного запроса оператора `В` можно обращаться к полям внешнего запроса, которые встречались до появления оператора (коррелированный подзапрос).
> Результат `В` с подзапросом двузначный (Истина/Ложь): результат сравнения с `NULL` трактуется как ложь.

## Приоритет операторов и NULL

### Приоритет логических операторов

Сначала вычисляются простые логические выражения, затем `НЕ`, затем `И`, в последнюю очередь `ИЛИ`:

```
НЕ  >  И  >  ИЛИ
```

```sql
-- Без скобок: трактуется как  А И (НЕ Б)  ИЛИ  В
ГДЕ А И НЕ Б ИЛИ В

-- Явные скобки убирают неоднозначность
ГДЕ (А ИЛИ В) И НЕ Б
```

> **Правило:** в любом нетривиальном условии расставляй скобки явно — это исключает ошибки приоритета.

### Правила сравнения значений и NULL

- Любая операция сравнения, в которой участвует хотя бы одно значение `NULL`, даёт результат `NULL`. Если результат условия (`ГДЕ`, `ПО`, `КОГДА`) равен `NULL` — условие считается **невыполненным** (как ложь).
- Поэтому `ГДЕ Поле <> &Значение` **не вернёт** строки, где `Поле = NULL`. Чтобы их получить, добавляй `ИЛИ Поле ЕСТЬ NULL`.
- Сравнение строк выполняется **без учёта регистра** и **без учёта концевых пробелов** (в отличие от встроенного языка, где `"bb" = "bb "` ложно, а в запросе — истинно).
- При сравнении значений разных типов используется приоритет типов (от низшего к высшему): `NULL` → `Неопределено` → `Булево` → `Число` → `Дата` → `Строка` → ссылочные типы.
- Нельзя сравнивать поля неограниченной длины (строка неограниченной длины, ХранилищеЗначения) и поле `ТипЗначения` плана видов характеристик.

```sql
-- Замена NULL на 0 (типичный паттерн после ЛЕВОГО СОЕДИНЕНИЯ)
ВЫБРАТЬ
    Товары.Наименование,
    ЕСТЬNULL(Остатки.КоличествоОстаток, 0) КАК Остаток
ИЗ Справочник.Товары КАК Товары
    ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.ТоварыНаСкладах.Остатки(&Дата) КАК Остатки
        ПО Товары.Ссылка = Остатки.Номенклатура
```

## Соединения (JOIN)

```sql
-- ВНУТРЕННЕЕ СОЕДИНЕНИЕ (INNER JOIN) — только совпадающие записи
ИЗ Справочник.Товары КАК Товары
    ВНУТРЕННЕЕ СОЕДИНЕНИЕ РегистрСведений.Цены.СрезПоследних КАК Цены
    ПО Товары.Ссылка = Цены.Товар

-- ЛЕВОЕ СОЕДИНЕНИЕ (LEFT JOIN) — все из левой + совпадения из правой
ИЗ Справочник.Товары КАК Товары
    ЛЕВОЕ СОЕДИНЕНИЕ РегистрСведений.Цены.СрезПоследних КАК Цены
    ПО Товары.Ссылка = Цены.Товар

-- ПРАВОЕ СОЕДИНЕНИЕ (RIGHT JOIN) — все из правой + совпадения из левой
ИЗ Справочник.Товары КАК Товары
    ПРАВОЕ ВНЕШНЕЕ СОЕДИНЕНИЕ РегистрСведений.Цены.СрезПоследних КАК Цены
    ПО Товары.Ссылка = Цены.Товар

-- ПОЛНОЕ СОЕДИНЕНИЕ (FULL JOIN) — все из обеих таблиц
ИЗ Справочник.Товары КАК Товары
    ПОЛНОЕ СОЕДИНЕНИЕ РегистрСведений.Цены.СрезПоследних КАК Цены
    ПО Товары.Ссылка = Цены.Товар
```

> Ключевые слова `ВНЕШНЕЕ` и `ВНУТРЕННЕЕ` можно опускать, но они повышают читаемость.
> Строки, для которых не нашлось соответствия, содержат `NULL` в полях «недостающего» источника.
>
> **Важно:** условие `ГДЕ` на поле правой таблицы при `ЛЕВОМ СОЕДИНЕНИИ` неявно превращает его во `ВНУТРЕННЕЕ` (потому что `NULL` не проходит условие). Решение — выносить такие условия в подзапрос/временную таблицу или в параметры виртуальной таблицы.

### Несколько соединений

```sql
ИЗ Документ.РасходнаяНакладная КАК Накладная
    ЛЕВОЕ СОЕДИНЕНИЕ Справочник.Контрагенты КАК Контрагент
        ПО Накладная.Покупатель = Контрагент.Ссылка
    ЛЕВОЕ СОЕДИНЕНИЕ РегистрСведений.Цены.СрезПоследних КАК Цены
        ПО Накладная.Товар = Цены.Товар
```

## СГРУППИРОВАТЬ ПО и ИМЕЮЩИЕ

```sql
ВЫБРАТЬ
    Состав.Товар КАК Товар,
    СУММА(Состав.Количество) КАК КолВо,
    СУММА(Состав.Сумма) КАК Сумма
ИЗ Документ.РасходнаяНакладная.Состав КАК Состав
СГРУППИРОВАТЬ ПО
    Состав.Товар
```

> В списке `ВЫБРАТЬ` при наличии `СГРУППИРОВАТЬ ПО` допустимы только: поля группировки + агрегатные функции (`СУММА`, `МИНИМУМ`, `МАКСИМУМ`, `СРЕДНЕЕ`, `КОЛИЧЕСТВО`).
>
> В `СГРУППИРОВАТЬ ПО` указываются **имена полей**, не псевдонимы.
>
> **Нельзя** использовать одно и то же поле и для группировки, и внутри агрегатной функции — на разных СУБД это даёт ошибку.
>
> Если `СГРУППИРОВАТЬ ПО` отсутствует, но есть агрегатные функции — все записи сворачиваются в одну строку.

### ИМЕЮЩИЕ — фильтр по агрегатам

```sql
СГРУППИРОВАТЬ ПО
    Состав.Ссылка.Покупатель,
    Состав.Товар
ИМЕЮЩИЕ
    СУММА(Состав.Сумма) > 50000
```

> `ИМЕЮЩИЕ` — аналог `ГДЕ`, но применяется **после** группировки, к агрегатным значениям. В `ГДЕ` агрегатные функции использовать нельзя.
> В условии `ИМЕЮЩИЕ` можно использовать только агрегатные функции и поля, по которым идёт группировка.

## Группирующие наборы

`СГРУППИРОВАТЬ ПО ГРУППИРУЮЩИМ НАБОРАМ` позволяет за **один проход** таблицы вычислить сразу несколько разных группировок (вместо нескольких запросов через `ОБЪЕДИНИТЬ`). Поддерживается платформой 8.3.x.

```sql
-- Остатки сразу: по складам, по товарам, по товарам+складам
ВЫБРАТЬ
    Остатки.Номенклатура КАК Номенклатура,
    Остатки.Склад КАК Склад,
    СУММА(Остатки.КоличествоОстаток) КАК КоличествоОстаток
ИЗ
    РегистрНакопления.ТоварыНаСкладах.Остатки КАК Остатки
СГРУППИРОВАТЬ ПО ГРУППИРУЮЩИМ НАБОРАМ
    (
        (Остатки.Склад),
        (Остатки.Номенклатура),
        (Остатки.Номенклатура, Остатки.Склад)
    )
```

> Набор агрегатных функций единый для всех наборов. Поле, не участвующее в агрегации, должно входить хотя бы в один набор. Поддерживается только для таблиц верхнего уровня (включая виртуальные).
>
> **Скобки значимы.** `((Номенклатура, Склад))` — один набор из двух полей (эквивалент обычного `СГРУППИРОВАТЬ ПО Номенклатура, Склад`). `(Номенклатура, Склад)` — **два** набора, каждый по одному полю.

### СГРУППИРОВАНОПО — пометка строки итога

Функция `СГРУППИРОВАНОПО(<Поле>)` возвращает `Истина`, если в данной строке по этому полю выполнялась группировка. Удобно подставлять «Все …» в строках агрегации:

```sql
ВЫБРАТЬ
    ВЫБОР КОГДА СГРУППИРОВАНОПО(Остатки.Номенклатура)
        ТОГДА Остатки.Номенклатура
        ИНАЧЕ ЗНАЧЕНИЕ(Справочник.Номенклатура.ПустаяСсылка)
    КОНЕЦ КАК Номенклатура,
    СУММА(Остатки.КоличествоОстаток) КАК КоличествоОстаток
ИЗ
    РегистрНакопления.ТоварыНаСкладах.Остатки КАК Остатки
СГРУППИРОВАТЬ ПО ГРУППИРУЮЩИМ НАБОРАМ
    (
        (Остатки.Склад),
        (Остатки.Номенклатура)
    )
```

## ВЫБОР (CASE)

Возвращает одно из значений по набору условий. Альтернатив `КОГДА … ТОГДА` может быть сколько угодно; они обрабатываются последовательно, первая истинная завершает выбор. `ИНАЧЕ` — значение по умолчанию.

```sql
ВЫБРАТЬ
    Номенклатура.Наименование,
    ВЫБОР
        КОГДА Номенклатура.ЭтоГруппа ТОГДА "Группа"
        КОГДА Номенклатура.ЗакупочнаяЦена > 1000 ТОГДА "> 1000"
        КОГДА Номенклатура.ЗакупочнаяЦена > 100 ТОГДА "100 – 1000"
        КОГДА Номенклатура.ЗакупочнаяЦена > 0 ТОГДА "0 – 100"
        ИНАЧЕ "Не задана"
    КОНЕЦ КАК Категория
ИЗ Справочник.Номенклатура КАК Номенклатура
```

Применения:
- В списке выборки (вычисляемое поле).
- В `ГДЕ`, `ИМЕЮЩИЕ`, `УПОРЯДОЧИТЬ ПО`, `ИТОГИ`.
- Для модуля числа (функции `АБС` в языке запросов нет):

```sql
ВЫБОР КОГДА Разница < 0 ТОГДА -Разница ИНАЧЕ Разница КОНЕЦ КАК МодульРазницы
```

> **Ограничения:**
> - `ВЫБОР` **нельзя** вложить внутрь агрегатной функции (`СУММА(ВЫБОР …)` допустимо, а `АБС`-подобный приём над агрегатом в `ИМЕЮЩИЕ` — нет; там используются два условия, см. `functions-and-expressions.md`).
> - Выражение в `ТОГДА`/`ИНАЧЕ` не может одновременно содержать поле неограниченной длины (строка/хранилище значений) и поле других типов.

## ИТОГИ

Рассчитывают промежуточные и общие итоги.

```sql
ВЫБРАТЬ
    Состав.Ссылка.Поставщик КАК Поставщик,
    Состав.Товар КАК Товар,
    СУММА(Состав.Количество) КАК Количество
ИЗ Документ.ПриходнаяНакладная.Состав КАК Состав
СГРУППИРОВАТЬ ПО
    Состав.Ссылка.Поставщик,
    Состав.Товар
ИТОГИ
    СУММА(Количество)
ПО
    ОБЩИЕ,
    Поставщик
```

> `ОБЩИЕ` — строка с итогом по всему результату. После неё перечисляются поля группировок (контрольные точки).
> `ИТОГИ` работают **поверх** объединённых запросов.
> Если контрольная точка — ссылка на справочник, можно считать итоги по иерархии: `ПО Номенклатура ИЕРАРХИЯ` (или `ТОЛЬКО ИЕРАРХИЯ` — только иерархические итоги).
> При итогах по полю типа `Дата` доступно дополнение периодами: `ПО Период ПЕРИОДАМИ(МЕСЯЦ, &Нач, &Кон)`.

## УПОРЯДОЧИТЬ ПО

```sql
УПОРЯДОЧИТЬ ПО
    Дата,                      -- по возрастанию (по умолчанию)
    Сумма УБЫВ,                -- по убыванию
    Контрагент.Наименование    -- разыменование через точку
```

> Упорядочивание результата **обязательно** в любом работоспособном запросе. Без него порядок строк не определён и может различаться на разных СУБД.

### ИЕРАРХИЯ в упорядочивании

```sql
УПОРЯДОЧИТЬ ПО
    Наименование ИЕРАРХИЯ
```

Возвращает записи с соблюдением иерархии справочника (группы → элементы). Имеет смысл, только если источник — таблица самого справочника, а не другая таблица со ссылкой на него.

### АВТОУПОРЯДОЧИВАНИЕ

```sql
АВТОУПОРЯДОЧИВАНИЕ
```

Добавляет автоматическую сортировку на основе основного представления объекта (для справочников — код/наименование, для документов — дата). Используется вместо явного `УПОРЯДОЧИТЬ ПО` для простых случаев.

## ОБЪЕДИНИТЬ / ОБЪЕДИНИТЬ ВСЕ

Дополняет строки одного запроса строками другого.

```sql
ВЫБРАТЬ
    Заказ.Клиент КАК Клиент,
    Заказ.Товар КАК Товар,
    СУММА(Заказ.Количество) КАК Заказано,
    СУММА(0) КАК Продано
ИЗ Документ.ЗаказТовара.Состав КАК Заказ
СГРУППИРОВАТЬ ПО
    Заказ.Ссылка.Клиент,
    Заказ.Товар

ОБЪЕДИНИТЬ ВСЕ

ВЫБРАТЬ
    Накладная.Ссылка.Покупатель,
    Накладная.Товар,
    СУММА(0),
    СУММА(Накладная.Количество)
ИЗ Документ.РасходнаяНакладная.Состав КАК Накладная
СГРУППИРОВАТЬ ПО
    Накладная.Ссылка.Покупатель,
    Накладная.Товар

ИТОГИ ПО ОБЩИЕ, Клиент
```

> Имена полей результата берутся из **первого** запроса. Поля второго сопоставляются по порядку.
> Количество полей в обоих запросах должно совпадать. Если типы полей различаются — результат получает составной тип.
>
> `ОБЪЕДИНИТЬ` — удаляет полностью дублирующиеся строки (дорого). `ОБЪЕДИНИТЬ ВСЕ` — оставляет все строки. **Рекомендуется всегда использовать `ОБЪЕДИНИТЬ ВСЕ`**, если нет специальной потребности в дедупликации.

## Временные таблицы и пакетные запросы

Временная таблица создаётся ключевым словом `ПОМЕСТИТЬ`.

```sql
// Запрос 1 — создание временной таблицы
ВЫБРАТЬ
    Состав.Товар,
    Состав.Ссылка.Дата КАК Дата,
    Состав.Ссылка.Поставщик
ПОМЕСТИТЬ ПоступленияЗаПериод
ИЗ
    Документ.ПриходнаяНакладная.Состав КАК Состав
ГДЕ
    Состав.Ссылка.Дата МЕЖДУ &НачДата И &КонДата
ИНДЕКСИРОВАТЬ ПО
    Товар
;

// Запрос 2 — использование временной таблицы
ВЫБРАТЬ
    Товары.Наименование,
    Пост.Дата,
    Пост.Поставщик
ИЗ
    Справочник.Товары КАК Товары
    ЛЕВОЕ СОЕДИНЕНИЕ ПоступленияЗаПериод КАК Пост
        ПО Товары.Ссылка = Пост.Товар
УПОРЯДОЧИТЬ ПО
    Товары.Наименование ИЕРАРХИЯ
```

> Запросы в пакете разделяются символом `;`.
> `ИНДЕКСИРОВАТЬ ПО` — создаёт индекс по полям временной таблицы для ускорения последующих соединений. Указывать поля, которые будут участвовать в условиях соединения или отбора.
>
> **Предпочтительнее вложенных запросов** для сложных случаев: лучше читается, оптимизируется платформой.

### ДОБАВИТЬ — дозапись в существующую ВТ

Добавляет строки в уже созданную временную таблицу (структуры должны совпадать).

```sql
ВЫБРАТЬ
    Товары.Наименование КАК Наименование
ПОМЕСТИТЬ СписокНаименований
ИЗ Справочник.Товары КАК Товары
;
ВЫБРАТЬ
    Услуги.Наименование КАК Наименование
ДОБАВИТЬ СписокНаименований
ИЗ Справочник.Услуги КАК Услуги
```

> ⚠️ У поля выборки **непосредственно перед** `ДОБАВИТЬ` обязательно должен быть псевдоним. Иначе слово `ДОБАВИТЬ` будет воспринято как псевдоним поля и запрос упадёт.

### ИНДЕКСИРОВАТЬ ПО НАБОРАМ и УНИКАЛЬНО

Несколько индексов на одной ВТ; уникальный индекс — только один.

```sql
ВЫБРАТЬ
    Номенклатура.Код КАК Код,
    Номенклатура.Наименование КАК Наименование,
    Номенклатура.Артикул КАК Артикул
ПОМЕСТИТЬ ДанныеТоваров
ИЗ Справочник.Номенклатура КАК Номенклатура
ИНДЕКСИРОВАТЬ ПО НАБОРАМ (
    (Код, Наименование),
    (Артикул) УНИКАЛЬНО
)
```

> Индексы создаются только в запросе с `ПОМЕСТИТЬ`. Индексируемые поля должны быть в списке выборки. Уникальный индекс нельзя использовать для контроля уникальности данных (поведение СУБД различается).

### УНИЧТОЖИТЬ и ДЛЯ ИЗМЕНЕНИЯ

```sql
-- Явно удалить временную таблицу
УНИЧТОЖИТЬ ПоступленияЗаПериод

-- Заблокировать считываемые данные в транзакции (read for update)
ВЫБРАТЬ ...
ПОМЕСТИТЬ ВТ
ИЗ Документ.РасходнаяНакладная КАК РасходнаяНакладная
ГДЕ РасходнаяНакладная.Ссылка В (&Документы)
ДЛЯ ИЗМЕНЕНИЯ
```

> `ДЛЯ ИЗМЕНЕНИЯ` блокирует данные от чтения другими транзакциями до её завершения; нельзя применять к ВТ из внешнего источника. Для read-only аналитики обычно не нужно.

## Вложенные запросы

Используются как источник данных или в условиях отбора.

```sql
// Вложенный запрос в условии ГДЕ (оператор В)
ВЫБРАТЬ
    Расход.Ссылка КАК Документ,
    Расход.Покупатель
ИЗ
    Документ.РасходнаяНакладная КАК Расход
ГДЕ
    Расход.Состав.Товар В (
        ВЫБРАТЬ
            Состав.Товар
        ИЗ
            Документ.ПриходнаяНакладная.Состав КАК Состав
        ГДЕ
            Состав.Ссылка = &Документ
    )

// Вложенный запрос как источник (в ИЗ)
ИЗ
    Справочник.Товары КАК Товары
    ЛЕВОЕ СОЕДИНЕНИЕ (
        ВЫБРАТЬ
            Состав.Товар,
            Состав.Ссылка.Дата КАК Дата
        ИЗ
            Документ.ПриходнаяНакладная.Состав КАК Состав
        ГДЕ
            МЕСЯЦ(Состав.Ссылка.Дата) = 11
    ) КАК Поступления
    ПО Товары.Ссылка = Поступления.Товар

// Вложенный запрос в параметре виртуальной таблицы
ИЗ РегистрСведений.Цены.СрезПоследних(
        ,
        Товар В (ВЫБРАТЬ Состав.Товар ИЗ Документ.РасходнаяНакладная.Состав КАК Состав ГДЕ Состав.Ссылка = &Документ)
   ) КАК Цены
```

> **Рекомендация:** в сложных запросах предпочитать временные таблицы вложенным запросам — лучше читаемость и оптимизация.
> Не использовать подзапросы в условии соединения (`ПО`) — это сильно замедляет запрос.
> Не соединять виртуальные таблицы через вложенный запрос — антипаттерн производительности.

## Иерархия

```sql
// Отбор элементов, входящих в иерархию группы
ГДЕ Товары.Ссылка В ИЕРАРХИИ (&ГруппаТоваров)

// Упорядочивание с соблюдением иерархии
УПОРЯДОЧИТЬ ПО Наименование ИЕРАРХИЯ

// Только непосредственные дочерние элементы группы
ГДЕ Товары.Родитель = &Группа
```

> `В ИЕРАРХИИ` включает в результат **сам** переданный элемент.
> В качестве множества справа от `В ИЕРАРХИИ` может быть и результат вложенного запроса.

## Псевдонимы

```sql
// Псевдоним таблицы
ИЗ Справочник.Товары КАК Товары

// Псевдоним поля
ВЫБРАТЬ Товары.Наименование КАК Название

// Без КАК (допустимо, но менее читаемо)
ИЗ Справочник.Товары Товары
```

> `КАК` обязательно когда: несколько таблиц с полями одинаковых имён; имя псевдонима отличается от имени поля; улучшает читаемость.
> Псевдонимы в запросе не могут совпадать. Если источнику назначен псевдоним, обращаться к нему по имени таблицы уже нельзя.

## Параметры запроса

```sql
// В условиях
ГДЕ Дата >= &НачалоПериода

// В параметрах виртуальных таблиц
РегистрСведений.Цены.СрезПоследних(&Дата, )

// Список значений
ГДЕ Статус В (&СписокСтатусов)
```

> **Всегда предпочитать параметры** (`&Имя`) конкатенации строк в тексте запроса. Параметры безопасны, эффективны и позволяют переиспользовать скомпилированный запрос.

## Оформление и правила написания

1. Ключевые слова — заглавными буквами (`ВЫБРАТЬ`, `ИЗ`, `ГДЕ`)
2. Каждое поле выборки — на отдельной строке со смещением
3. Секции запроса разделяются пустой строкой
4. Вложенные запросы — со смещением относительно внешнего
5. Псевдонимы задаются для всех таблиц и ключевых полей
6. В `СГРУППИРОВАТЬ ПО` поля — каждое на отдельной строке
7. Запросы в пакете разделяются `;`

```sql
// Канонический пример оформления
ВЫБРАТЬ
    Накладная.Ссылка.Покупатель КАК Покупатель,
    Накладная.Товар КАК Товар,
    СУММА(Накладная.Количество) КАК КолВо,
    СУММА(Накладная.Сумма) КАК Сумма
ИЗ
    Документ.РасходнаяНакладная.Состав КАК Накладная
ГДЕ
    Накладная.Ссылка.Дата МЕЖДУ &НачДата И &КонДата
СГРУППИРОВАТЬ ПО
    Накладная.Ссылка.Покупатель,
    Накладная.Товар
УПОРЯДОЧИТЬ ПО
    Покупатель,
    Товар
```

## Оптимизация запросов (Глава 4, Хрусталёва)

### Как работают индексы

СУБД ищет записи по индексу — упорядоченному дереву значений проиндексированных полей. Чтобы индекс использовался эффективно, три обязательных условия:

1. Индекс содержит все поля из условия запроса
2. Эти поля стоят **в начале** индекса
3. Поля идут **подряд**, без «пропусков»

**Пример:** индекс `Период + Организация + Склад + Номенклатура`

```sql
-- Эффективно: все поля с начала индекса, без пропусков
ГДЕ Период = &П И Организация = &О И Склад = &С И Номенклатура = &Н

-- Частично: Склад пропущен → сканирование индекса
ГДЕ Период = &П И Организация = &О И Номенклатура = &Н
```

### Автоматические индексы платформы

| Таблица | Индексы |
|---------|---------|
| Справочники, документы | По `Ссылка`; по `Код + Ссылка`; по `Наименование + Ссылка` |
| Движения регистров | По `Период + Регистратор + НомерСтроки`; по `Регистратор + НомерСтроки` |
| Итоги регистров накопления | По `Период + Измерение1 + ... + ИзмерениеN` |
| Итоги регистров бухгалтерии | По `Период + Счёт + Измерение1 + ... + ИзмерениеN` |

> Порядок измерений в индексе = порядок измерений в конфигураторе. Меняешь порядок → меняется индекс.

### Условия, которые используют индекс

Индексы работают в:
- `ГДЕ`
- `ПО` (условие соединения)
- параметрах виртуальных таблиц
- `ИМЕЮЩИЕ`

### Антипаттерны производительности

| Антипаттерн | Проблема | Решение |
|-------------|---------|---------|
| Запрос в цикле | N запросов вместо одного | Вынести запрос из цикла |
| `ГДЕ ГОД(Дата) = 2024` | Функция от поля отключает индекс | `ГДЕ Дата МЕЖДУ ДАТАВРЕМЯ(2024,1,1) И ДАТАВРЕМЯ(2024,12,31,23,59,59)` |
| Параметры ВТ не заданы | Платформа читает всю таблицу регистра | Всегда указывать параметры в скобках |
| `СОЕДИНЕНИЕ` с ВТ напрямую | СУБД не может оптимизировать | Поместить ВТ во временную таблицу, затем соединять |
| `ЛЕВОЕ СОЕДИНЕНИЕ` с ВТ + `ГДЕ` на поле правой таблицы | Левое соединение становится внутренним | Условие на ВТ передавать в параметры ВТ |
| Вложенный запрос в условии соединения | Не оптимизируется СУБД | Временные таблицы |
| `Накладная.Товар.Ссылка` — через точку | Неявное соединение | Явное соединение |
| Составной тип без ВЫРАЗИТЬ | Неявное соединение по всем типам | `ВЫРАЗИТЬ(Поле КАК Документ.Реализация)` |
| `ПОДСТРОКА` в основном условии `ГДЕ` | Отключает индекс | Использовать только в дополнительных условиях |
| Арифметика в основном условии `ГДЕ` | Отключает индекс | Вычислять значение до запроса, передавать параметром |
| `ОБЪЕДИНИТЬ` несколько похожих группировок | Несколько проходов таблицы | `СГРУППИРОВАТЬ ПО ГРУППИРУЮЩИМ НАБОРАМ` |

### ИНДЕКСИРОВАТЬ ПО во временных таблицах

```sql
ВЫБРАТЬ
    Состав.Товар,
    Состав.Количество
ПОМЕСТИТЬ ПоступленияЗаПериод
ИЗ
    Документ.ПриходнаяНакладная.Состав КАК Состав
ГДЕ
    Состав.Ссылка.Дата МЕЖДУ &НачДата И &КонДата
ИНДЕКСИРОВАТЬ ПО
    Товар   -- поле, которое будет в условии соединения
```

> `ИНДЕКСИРОВАТЬ ПО` создаёт индекс на временную таблицу. Указывай поля, которые используются в `ПО` (условии соединения) или в `ГДЕ` следующего запроса.
