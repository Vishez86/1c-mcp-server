# Версия и provenance справочника

## Версия справочника

- Целевая версия платформы: `1С:Предприятие 8.3.37`.
- Область: язык запросов 1С, выполнение запросов из BSL, виртуальные таблицы стандартных объектов метаданных.
- Текущий формат: локальный skill `1c-query-language` с reference-файлами в `references/`.
- Дата фиксации версии в справочнике: `2026-06-22`.

Если пользователь явно называет другую версию платформы, не переносить правила из этого справочника автоматически. Нужно проверить отличие версии или явно сказать, что ответ основан на базе `8.3.37`.

## Источники и приоритеты

1. Официальная документация ИТС, «Глава 8. Работа с запросами», платформа `8.3.37`.
   - Приоритет: высший для синтаксиса, семантики операторов, функций языка запросов, правил выполнения и BSL API.
   - Если справочник или модель противоречат официальной документации этой версии, считать верной официальную документацию.

2. Е.Ю. Хрусталёва, «Язык запросов 1С:Предприятия 8».
   - Приоритет: методика написания запросов, практические паттерны, оптимизация, объяснения производительности.
   - Не использовать как источник для утверждений о наличии синтаксиса, если это расходится с официальной документацией `8.3.37`.

3. Скриншоты и наблюдения из конфигуратора БП КОРП.
   - Приоритет: состав полей конкретных виртуальных таблиц и объектов конфигурации там, где официальная глава 8 описывает механику, но не перечисляет поля конкретной конфигурации.
   - Такие сведения считать конфигурационно-зависимыми. Для другой конфигурации или релиза БП КОРП нужно сверять метаданные заново.

4. Практические проверки через MCP tools / живой endpoint 1С.
   - Приоритет: высший для фактических данных конкретной базы и текущего состава метаданных.
   - Не использовать результаты живого endpoint как доказательство общеплатформенного правила, если это может быть особенностью конфигурации, прав пользователя или версии расширения.

## Границы применимости

- Справочник описывает язык запросов платформы `8.3.37`, но не заменяет метаданные конкретной информационной базы.
- Имена регистров, реквизитов, измерений, ресурсов, субконто и табличных частей нужно проверять через доступные MCP tools или метаданные, если задача зависит от конкретной базы.
- Поля виртуальных таблиц регистров могут зависеть от вида регистра, включенных настроек учета, состава измерений и ресурсов.
- Примеры запросов являются шаблонами. Перед использованием в рабочей базе нужно адаптировать имена объектов, параметры, права доступа и периодичность.

## Правила разрешения конфликтов

- Общий синтаксис и функции: официальная документация `8.3.37` важнее книги, примеров и памяти модели.
- Производительность и стиль: официальные правила важнее; затем Хрусталёва; затем локальные практики проекта.
- Состав метаданных конкретной базы: live MCP/metadata inspection важнее markdown-справочника.
- Если источник неясен, не выдавать утверждение как факт. Формулировать как предположение и предложить проверку.

## Правила обновления справочника

- При добавлении нового правила указывать, относится ли оно к платформе, методике или конкретной конфигурации.
- Не смешивать платформенные правила `8.3.37` с особенностями БП КОРП без явной пометки.
- Если обновляется целевая версия платформы, проверить все reference-файлы на устаревшие ограничения и обновить эту страницу.
- Для спорных мест добавлять короткую пометку о происхождении рядом с правилом или примером.
