## 1. Цель тестирования

Доказать, что реализация трёх доработок:

1. **F4-fix** — отклоняет несуществующее поле ВТ, записанное **без алиаса**, при единственном источнике-ВТ (`validation_failed_before_run`, движок не вызван), и при этом **не** даёт ложных отказов на валидных неквалифицированных конструкциях (функции, агрегаты, выражения, выходные алиасы, параметры);
2. **F5-fix** — генератор `ОборотыДтКт` больше не содержит фантомных `СуммаОборотДт`/`СуммаОборотКт`, оставаясь надмножеством реальных колонок;
3. **F6-fix** — при `validate_before_run=false` и сработавшем pre-flight в `warnings[]` присутствует сообщение об игнорировании флага;

а также что **не деградировало** базовое поведение (квалифицированные негативы/позитивы, регистры накопления, `vt_param_field_error`, security, паритет pre-flight ↔ метаданные).

Тестирование пройдено при выполнении всех Exit-критериев (§8) и зелёном контрактном прогоне в трёх режимах ответа.

## 3. Тестовые константы (БП КОРП)

**Бух-регистр:** `РегистрБухгалтерии.Хозрасчетный`
**Снимок для `Остатки`:** `&Период = ДАТАВРЕМЯ(2026,6,29)`
**Период для оборотных ВТ:** `&ПериодНачало = ДАТАВРЕМЯ(2026,1,1)`, `&ПериодКонец = ДАТАВРЕМЯ(2026,6,29)`
**Накопительный регистр (выбран через `list_registers`):** `РегистрНакопления.ВзаиморасчетыСДепонентами` (ресурс Сумма; поля Остатки: СуммаОстаток, ФизическоеЛицо, Ведомость, Организация; поля Обороты: СуммаОборот, СуммаПриход, СуммаРасход + служебные).

**Авторитетные факты по `ОборотыДтКт` (оракул F5-fix):**

- **есть:** `СуммаОборот` (балансовый), `ВалютнаяСуммаОборотДт/Кт`, `КоличествоОборотДт/Кт`, `Сумма{НУ|ПР|ВР}ОборотДт/Кт`, `СчетДт/Кт`, `СубконтоДт1..3`, `СубконтоКт1..3`;
- **нет (устраняется F5-fix):** `СуммаОборотДт`, `СуммаОборотКт`;
- **нет (базовый anti-union):** общих `Субконто1..3`, голого `КоличествоОборот`, голого `СуммаПРОборот`.

**Контраст:** в ВТ `Обороты` (не ДтКт) поля `СуммаОборотДт`/`СуммаОборотКт` **валидны** — используется как ловушка против регресса F5-fix.

## 4. Группы тест-кейсов

### TG-A. F4-fix — негативы без алиаса, единственный источник-ВТ (приёмка 1)

Все запросы — единственный источник-ВТ, поле в `ВЫБРАТЬ` без алиаса.

| ID | Запрос (фрагмент) | Источник | Ожидаемое |
|---|---|---|---|
| NA-01 | `ВЫБРАТЬ СуммаОстатокИтого ИЗ …Хозрасчетный.Остатки(&Период)` | Остатки | `validation_failed_before_run`; движок не вызван; кандидат `СуммаОстаток` |
| NA-02 | `ВЫБРАТЬ КоличествоОборот ИЗ …Хозрасчетный.ОборотыДтКт(&ПН,&ПК)` | ОборотыДтКт | отказ pre-flight; кандидаты `КоличествоОборотДт/Кт` |
| NA-03 | `ВЫБРАТЬ Субконто1 ИЗ …Хозрасчетный.ОборотыДтКт(&ПН,&ПК)` | ОборотыДтКт | отказ; кандидаты `СубконтоДт1`/`СубконтоКт1` |
| NA-04 | `ВЫБРАТЬ СчетXX ИЗ …Хозрасчетный.Остатки(&Период)` | Остатки | отказ; кандидат `Счет` |
| NA-05 | `ВЫБРАТЬ СуммаОстатокXXX ИЗ …ВзаиморасчетыСДепонентами.Остатки(&Период)` | Накопл. Остатки | отказ pre-flight; кандидат `СуммаОстаток` |

**Ассерты (каждый):** `error_code=validation_failed_before_run`; отсутствует `platform_message`; `suggestions` содержит «движок 1С не вызывался»; `available_fields` непустой, `available_fields_source="virtual_table"`; кандидатов ≤ 3; `hint` содержит имя поля и «не существует».

### TG-B. F4-fix — ноль ложных отказов на валидных неквалиф. конструкциях (приёмка 3) — КРИТИЧНО

Единственный источник-ВТ; каждая конструкция валидна и **не должна** отклоняться pre-flight.

| ID | Запрос (фрагмент) | Ожидаемое |
|---|---|---|
| PA-01 | `ВЫБРАТЬ СуммаОстаток ИЗ …Остатки(&Период)` | успех (голое валидное поле) |
| PA-02 | `ВЫБРАТЬ СУММА(СуммаОстаток) КАК Всего ИЗ …Остатки(&Период)` | успех (`СУММА` — не поле; алиас `Всего` не проверяется) |
| PA-03 | `ВЫБРАТЬ СуммаОстаток КАК СуммаОстатокИтого ИЗ …Остатки(&Период)` | успех (выходной алиас = имя несуществующего поля — **не** триггерит отказ) |
| PA-04 | `ВЫБРАТЬ СуммаОстаток * 2 КАК Удвоенная ИЗ …Остатки(&Период)` | успех (литерал `2` и выражение не проверяются как поля) |
| PA-05 | `ВЫБРАТЬ СуммаОстаток, &Метка КАК Метка ИЗ …Остатки(&Период)` (параметр `Метка` в parameters) | успех (параметр `&Метка` — не поле) |
| PA-06 | `ВЫБРАТЬ ВЫБОР КОГДА СуммаОстаток > 0 ТОГДА 1 ИНАЧЕ 0 КОНЕЦ КАК Признак ИЗ …Остатки(&Период)` | успех (`ВЫБОР/КОГДА/ТОГДА/ИНАЧЕ/КОНЕЦ` — ключевые слова, не поля) |

**Критично:** хотя бы один pre-flight-отказ в TG-B = провал релиза (ложный отказ валидного запроса). Допускается только штатная валидационная ошибка, не связанная с pre-flight полей ВТ.

### TG-C. F4-fix — при JOIN (≥2 источника) неквалиф. поля не проверяются (приёмка 4)

| ID | Запрос | Ожидаемое |
|---|---|---|
| JA-01 | `ВЫБРАТЬ СуммаОстатокИтого ИЗ …Остатки(&Период) КАК О, …Обороты(&ПН,&ПК) КАК Об` (битое неквалиф. поле) | **нет** `validation_failed_before_run` от неквалиф. пути; запрос уходит на движок (там возможна `field_not_found`/неоднозначность) |
| JA-02 | JOIN Остатки+Обороты, `Об.СуммаОборотХХ` (битое **квалиф.** поле) | `validation_failed_before_run`, `source_table=…Обороты` (регресс базового E-04) |

### TG-D. F4-fix — подзапросы/алиасы (регресс E-02, риск R2)

| ID | Запрос | Ожидаемое |
|---|---|---|
| SA-01 | `ВЫБРАТЬ П.С ИЗ (ВЫБРАТЬ Т.СуммаОстаток КАК С ИЗ …Остатки(&Период) КАК Т) КАК П` | успех; внешнее `П.С` не валидируется против ВТ; ложного отказа нет |
| SA-02 | подзапрос с единственным источником-ВТ и битым неквалиф. полем | граничный: либо отказ pre-flight по внутренней области, либо уход на движок; **ложного отказа на валидных полях нет** |

### TG-E. F5-fix — точность генератора `ОборотыДтКт` (приёмка 5, 6)

| ID | Проверка | Ожидаемое |
|---|---|---|
| GA-01 | набор полей ОборотыДтКт (через отказ pre-flight и `get_metadata_structure`) | **нет** `СуммаОборотДт`, `СуммаОборотКт`; **есть** `СуммаОборот`, `ВалютнаяСуммаОборотДт/Кт`, `КоличествоОборотДт/Кт`, `Сумма{НУ/ПР/ВР}ОборотДт/Кт` |
| GA-02 | `ВЫБРАТЬ Т.СуммаОборот ИЗ …ОборотыДтКт(&ПН,&ПК) КАК Т` | успех |
| GA-03 | `ВЫБРАТЬ Т.СуммаОборотДт ИЗ …ОборотыДтКт(&ПН,&ПК) КАК Т` | теперь `validation_failed_before_run` (раньше доходило до движка) — фантом устранён |
| GA-04 | сверка набора генератора с `common_fields` из `get_metadata_structure` | идентичны; набор ⊇ реальных колонок ВТ |
| GA-05 | `ВЫБРАТЬ Т.СуммаОборотДт ИЗ …Обороты(&ПН,&ПК) КАК Т` (контраст!) | **успех** — в ВТ `Обороты` это поле валидно (не задето F5-fix) |

**Ассерт G-03 anti-union:** для ОборотыДтКт `СуммаОборотДт ∉ set` и `СуммаОборотКт ∉ set`; при этом сохранены базовые anti-union (`Субконто1 ∉`, `КоличествоОборот ∉`, `СуммаПРОборот ∉`).

### TG-F. F6-fix — warning при `validate_before_run=false` (приёмка 7)

| ID | Запрос | Ожидаемое |
|---|---|---|
| WA-01 | `ВЫБРАТЬ Т.СуммаОстатокИтого ИЗ …Остатки(&Период) КАК Т`, `validate_before_run=false` | `validation_failed_before_run`; движок не вызван; в `warnings[]` — «validate_before_run=false проигнорирован…» |
| WA-02 | `ВЫБРАТЬ Т.СуммаОстаток ИЗ …Остатки(&Период) КАК Т`, `validate_before_run=false` | успех; предупреждения об игнорировании флага **нет** (warning только когда флаг реально проигнорирован) |

### TG-G. Регресс базового поведения (не сломать) — приёмка 2, 8

Должны остаться зелёными (из `TZ_test_preflight_vt_field_validation.md`):

- квалифицированные негативы N-01…N-04 (форма `Алиас.Поле`) → `validation_failed_before_run`, движок не вызван;
- позитивы P-01, P-02, P-03, P-05, P-06 → успех; P-04 — по исправленному оракулу (`СуммаОборот, ВалютнаяСуммаОборотДт, КоличествоОборотДт`);
- накопительные A-01…A-03;
- `vt_param_field_error` V-01 (код не подменён на `validation_failed_before_run`);
- `wildcard_select_forbidden` E-03;
- паритет C-01/C-02: `available_fields` (pre-flight) == `common_fields` (метаданные) — в т.ч. после правок §5;
- деградация `supported=false` (F-04): непокрытый вид ВТ → warning, без отказа.

## 5. Формат проверки ответа

Отказ pre-flight (`validation_failed_before_run`) — как в базовом тест-ТЗ. Машинные ассерты (на каждый негатив TG-A):

- `error_code == "validation_failed_before_run"`;
- `available_fields_source == "virtual_table"`;
- `available_fields` непустой и содержит поле из golden;
- `hint` содержит имя битого поля и «не существует»;
- кандидатов ≤ 3;
- отсутствует ключ `platform_message` (движок не вызывался).

Дополнительный ассерт F6-fix (WA-01): `warnings[]` содержит подстроку «validate_before_run=false проигнорирован».

Дополнительный ассерт F5-fix (GA-01/GA-04): множество полей ОборотыДтКт не содержит `СуммаОборотДт`/`СуммаОборотКт` и совпадает с `common_fields` метаданных.

## 8. Exit-критерии

1. TG-A — все неквалиф. негативы дают `validation_failed_before_run`, движок не вызван.
2. TG-B — **ноль** ложных отказов на валидных неквалиф. конструкциях (функции/агрегаты/выражения/выходные алиасы/параметры/CASE).
3. TG-C — при JOIN неквалиф. поля не проверяются; квалиф. проверяются по своему источнику.
4. TG-D — подзапросы/внешние алиасы не дают ложных отказов.
5. TG-E — генератор ОборотыДтКт без `СуммаОборотДт/Кт`, с `СуммаОборот`; надмножество и паритет сохранены; контраст в `Обороты` не задет.
6. TG-F — warning об игнорировании `validate_before_run=false` присутствует при отказе и отсутствует при успехе.
7. TG-G — базовый регресс (TG-1…TG-11) зелёный; P-04 исправлен; паритет C-01/C-02 сохранён.
8. TG-H — локале-независимость (юнит/стенд), безопасная деградация, кеш/перф подтверждены; контрактный прогон зелёный в 3 режимах; `reports/preflight_vt_retest.json` приложен.

**Блокеры релиза:** любой ложный отказ в TG-B/TG-C/TG-D, любой доказанный запрос из TG-A, дошедший до движка, а также регресс паритета pre-flight ↔ метаданные.
