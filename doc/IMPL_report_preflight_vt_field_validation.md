# IMPL: pre-flight валидация полей виртуальных таблиц в `run_1c_query`

**ТЗ:** `TZ_dev_preflight_vt_field_validation.md` (P1)
**Затронуто:** `MCP_Metadata.bsl`, `MCP_Query.bsl`, `MCP_Errors.bsl`, `scripts/mcp_contract_test.mjs`
**Принцип:** универсальность — генерация полей строится из реальной структуры регистра,
без привязки к конкретной конфигурации 1С.

## Что сделано

### 1. Универсальный генератор полей ВТ (`MCP_Metadata.bsl`)

Новая экспортная функция `ПолныйНаборПолейВиртуальнойТаблицы(ПолноеИмя, ИмяВТ)` →
`{ supported, fields, reason, vt_kind }`. Читает `Измерения/Ресурсы/Реквизиты/СтандартныеРеквизиты`
и применяет правила суффиксов платформы для `РегистрБухгалтерии`, `РегистрНакопления`,
`РегистрСведений`. Никогда не бросает исключение (при сбое — `supported=false`).

- Захардкоженные CSV-списки в `ВиртуальныеТаблицыРегистра` заменены вызовом генератора
  (`common_fields` теперь авторитетные и полные — закрывает F4 в метаданных).
- Для регистров накопления `common_fields` больше не пуст (закрывает F5).
- Контракт **надмножества**: набор ⊇ реальных колонок ВТ ⇒ ложные отказы исключены.
- Кастомные ресурсы разворачиваются из `ОМД.Ресурсы` (R1).
- Асимметрия ОборотыДтКт смоделирована: неразвёрнутый `{P}Оборот` — только для балансового
  ресурса «Сумма»; НУ/ПР/ВР/валютная/количественная — только Дт/Кт.

### 2. Pre-flight проверка (`MCP_Query.bsl`)

`ПроверитьПоляВиртуальныхТаблицПередВыполнением` вызывается **внутри**
`ВыполнитьЗапросСОграничениями` после `Валидировать` и **до** `Запрос.Выполнить()` (A-01,
обойти флагом `validate_before_run=false` нельзя).

- Находит источники-ВТ (`НайтиИсточникиЗапроса` + `ИмяВиртуальнойТаблицыИзRaw`).
- Определяет алиасы ВТ с учётом списка параметров `(...)` (`АлиасыИсточникаВиртуальнойТаблицы`).
- Извлекает поля, адресованные `Алиас.Поле` (первый сегмент; разыменование не валидируется);
  поля внутри скобок-параметров не трогаются (F-06 не дублируется).
- Доказанно отсутствующее поле → исключение с кодом `validation_failed_before_run` и
  диагностикой: `available_fields`, `available_fields_source="virtual_table"`, `source_table`,
  `field`, `object`, `hint` + Левенштейн-кандидаты (`ВариантыПохожихПолей`).
- Непокрытый вид/сбой интроспекции → warning, запрос идёт на движок (F-04, A-06).
- Per-request кеш `vt_fields_full:<имя>.<вт>` (A-03), общий с post-error диагностикой.
- Post-error путь (`ПоляВиртуальнойТаблицыДляДиагностики`) переведён на тот же генератор
  ⇒ `available_fields` в pre-flight и post-error идентичны (F-07, F-08).

### 3. Код ошибки (`MCP_Errors.bsl`)

`Код_ValidationFailedBeforeRun()` → `"validation_failed_before_run"`. Диагностика
поднимается в tool result штатным механизмом `MCP_Tools.СформироватьОшибкуРезультата`
(копирование полей из `details.diagnostics`).

### 4. Контрактные тесты (`scripts/mcp_contract_test.mjs`)

- `negative.run_1c_query_vt_field_rejected_pre_flight` — `СуммаПРОборот` в ОборотыДтКт теперь
  отсекается до движка с `validation_failed_before_run` (критерии 1, 7).
- `tool.vt_field_generator_authoritative_superset` — набор ⊇ авторитетной схемы; ОборотыДтКт
  без общих Субконто и без `СуммаПРОборот` (критерии 3, 4).
- `regression.run_1c_query_developed_balance_fields_not_rejected` — валидные Дт/Кт/Развёрнутый
  поля не отклоняются (критерий 2, защита от F4).
- `parity.pre_flight_and_metadata_fields_match` — `available_fields` == `common_fields` (F-08).
- `negative.run_1c_query_accumulation_vt_field_rejected_pre_flight` — регистр накопления
  тоже блокируется pre-flight (критерий 5).

## Проверка / деплой

1. BSL: нет `Перем` на верхнем уровне модулей; баланс `Функция/КонецФункции`,
   `Процедура/КонецПроцедуры` сходится.
2. `node --check scripts/mcp_contract_test.mjs` — зелёный.
3. Полный контракт прогонять **после** деплоя обновлённого расширения в 1С:
   `node scripts/mcp_contract_test.mjs --all-response-modes --out reports/mcp_contract_report.1c-korp.latest.json`.

## Границы

- Тип выражений и совместимость агрегатов не проверяются (вне scope ТЗ).

## Доп. фикс (2026-07-17): само-непротиворечивость pre-flight + развёрнутые остатки ОстаткиИОбороты

**Основание:** live-отчёт 2026-07-16 (BUH_KORP). `ОстаткиИОбороты.СуммаРазвернутыйКонечныйОстатокДт`
отклонялся `validation_failed_before_run`, хотя перечислялся в `available_fields` и предлагался как
«Возможная замена» — валидатор противоречил сам себе.

**Диагноз.** На HEAD проверка и список строятся из одного набора (F-07/F-08), поэтому точное
само-противоречие прямым запросом не воспроизводится. Оставались асимметрии сравнения:
`ПолеЕстьВНаборе` нормализовал `ВРег` без `СокрЛП` (генератор — `ВРег ∘ СокрЛП`), а подсказки
использовали префиксное `СтрНачинаетсяС` вместо точного равенства проверки.

**Сделано (`MCP_Query.bsl`):**
- Введена единая нормализация `НормализованныйКлючПоля` = `ВРег ∘ СокрЛП` (совпадает с
  `MCP_Metadata.ДобавитьПолеВНабор`). Через неё работают `ПолеЕстьВНаборе` и `ВариантыПохожихПолей`.
- Guard в `ВариантыПохожихПолей`: отклонённое поле не может быть предложено как замена самому себе
  (совпадение по нормализованному ключу исключается) — класс «advertise-but-reject» устранён структурно.

**Документация выровнена по реальному 1С-порядку** (`Развернутый` сразу после ресурса, перед
`Начальный/Конечный`): `MCP_Knowledge_1CQueryDocs.bsl`, `skills/1c-query-language/references/virtual-tables.md`,
`qa/golden_virtual_table_fields.md`. Раньше секция ОстаткиИОбороты ошибочно давала
`КонечныйРазвернутыйОстаток` и ресурс-суффикс — источник фантомных имён.

**Контрактные кейсы (`scripts/mcp_contract_test.mjs`):**
- `regression.run_1c_query_balance_turnover_developed_fields_not_rejected` — точный запрос из отчёта не отклоняется.
- `invariant.pre_flight_never_rejects_advertised_vt_field` — «advertised ⟹ accepted» на семействе развёрнутых остатков.
- `invariant.pre_flight_rejection_never_suggests_rejected_field` — guard: отклонённое поле не предлагается себе.
- `tool.vt_field_generator_authoritative_superset` — расширен: `ОстаткиИОбороты` ⊇ `СуммаРазвернутый{Начальный,Конечный}Остаток{Дт,Кт}`.

**Тест-ТЗ:** `doc/TZ_test_preflight_vt_developed_balance_self_consistency.md`.
