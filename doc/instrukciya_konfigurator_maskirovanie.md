## 1. Справочник `MCP_Маскирование`

Создать справочник со свойствами (А.1):

| Свойство | Значение |
|---|---|
| Имя | `MCP_Маскирование` |
| Синоним | `MCP: политика маскирования` |
| Иерархический | Ложь |
| Владельцы | нет |
| Длина кода | 9 (по умолчанию) |
| Длина наименования | 100 |
| Основное представление | В виде наименования |

Реквизит справочника — ровно один:

| Свойство | Значение |
|---|---|
| Имя | `Значение` |
| Тип | Строка |
| Длина | **неограниченная**: флажок «Неограниченная длина» = Истина (поле «Длина» при этом пустое) |
| Многострочный режим | Истина (для удобства просмотра) |
| Индексирование | Не индексировать |

Предопределённые элементы (вкладка «Прочее» → «Предопределённые») — **один**:

| Имя предопределённого | Наименование |
|---|---|
| `НастройкиМаскирования` | `Настройки маскирования` |

Второго элемента («Настройки по умолчанию») НЕТ — уточнение заказчика 11.08 (ТЗ §3.1). Обычные (непредопределённые) элементы движком не читаются; администратор может использовать их как именованные копии политики.

**ВНИМАНИЕ, имя предопределённого — контракт кода.** `MCP_Config.ТекстПолитикиМаскирования()` и запись из формы ищут элемент по `ИмяПредопределенныхДанных = "НастройкиМаскирования"`. Опечатка в имени = аварийный режим на контуре (максимальная маска) при живом справочнике.

## 2. Константа — НЕ создаётся

Рубильник — булев ключ `privacy.enabled` в **существующей** константе `MCP_ServerConfig` (ТЗ §3.2):

```json
"privacy": { "enabled": true }
```

- Ключа/секции/константы нет или JSON нечитаем → маскирование ВКЛЮЧЕНО (fail-closed; выключает только явная `false`).
- После миграции (шаг 6) секция `privacy` константы должна остаться только с этим ключом: оставленные ключи состава (`masked_fields`, `type_aliases`, …) игнорируются и дают предупреждение M-12 в `config_warnings`.
- Обработка рубильник **не пишет** — только показывает; переключение — правкой константы, как лимиты.

### 4.7. Условное оформление формы

1. **Пометка вида — только просмотр** (А.10.2): условие `ДеревоМетаданных.ЭтоВид = Истина` → оформляемое поле `ДеревоМетаданныхПометка`, «ТолькоПросмотр» = Истина. (В коде есть страховка — правка пометки вида откатывается, — но запрет интерфейсом обязателен.)
2. **Псевдоним и Префикс недоступны вне ссылочных объектов**: условие `ДеревоМетаданных.ПсевдонимДоступен = Ложь` → поля `ДеревоМетаданныхПсевдоним`, `ДеревоМетаданныхПрефикс`, «ТолькоПросмотр» = Истина.
3. **Префикс без псевдонима**: условие `ДеревоМетаданных.Псевдоним = Ложь` → поле `ДеревоМетаданныхПрефикс`, «ТолькоПросмотр» = Истина.

Модуль формы — целиком из `Forms/Форма/Module.bsl`.

**Модули не править построчно** — содержимое обоих заменить целиком готовыми файлами из репозитория (все переименования и удаления SDCH-логики уже внутри).

Реквизиты формы:

| Действие | Реквизиты |
|---|---|

Команды: удалить `НастройкиПоУмолчанию`, `ОчиститьИсторию`, `ДеревоНастройкиПоУмолчанию`, `ДеревоЗаписатьИзменения`, `ОчиститьИсториюДанныхТекущегоОбъекта`, `ПроверкаДанных`; переименовать `ЗаписатьИзменения` → `ЗаписатьПолитику`, `ПрочитатьЗаново` → `ПеречитатьПолитику`; добавить `ОчиститьВсе`, `ИмпортироватьИзServerConfig`.

Элементы: таблицу левого дерева `СписокМетаданных` переименовать в `ДеревоМетаданных`; правую таблицу перепривязать с `ДеревоМетаданных.РеквизитыОбъекта` на реквизит `ПоляОбъекта` и переименовать в `ПоляОбъекта`; элементы очистки/отладки/версии платформы удалить; добавить колонки `ДеревоМетаданныхПсевдоним`/`ДеревоМетаданныхПрефикс`, `ДекорацияНастройки` и `ГруппаНастройки` с содержимым (п. 4.5); события — п. 4.6; условное оформление — п. 4.7. Прочие формы заготовки (прогресс очистки), если есть, удалить целиком.

Внешний вариант обработки работоспособен (регистрация БСП сохранена), но справочник `MCP_Маскирование` и ключ `privacy.enabled` внешней обработкой не создаются — они идут изменением конфигурации/расширения.

## 5. Права

Все объекты (справочник, обработка) — только административным ролям. Сервисному пользователю HTTP-сервиса права на справочник НЕ нужны: движок читает политику в привилегированном режиме (M-3), форма пишет в привилегированном режиме.

## 6. Деплой и миграция (кратко, §7.2 ТЗ)

1. Одной сборкой: справочник + обработка + изменённые `MCP_Config.bsl`, `MCP_Security.bsl`. Новая сборка без справочника = аварийный режим (это правильно, но живой контур так не оставлять).
2. Открыть обработку → «Ещё» → «Импортировать из MCP_ServerConfig» → сверить предпросмотр JSON → «Записать». Форма сразу покажет, как сервер понял политику (enabled, счётчики, предупреждения).
3. Проверка эквивалентности на канарейке ERP_DEMO первой.
4. Из секции `privacy` константы `MCP_ServerConfig` удалить всё, кроме `"enabled": true` (до удаления работает предупреждение M-12).
5. Парный маркер деплоя: `engine_revision` = `2026-08-11.1` И поведение — `get_current_user_context` отвечает, в privacy-блоке НЕТ ключей `organization_aliases`/`person_aliases`, `list_metadata_objects` возвращает имена типов.

## 6a. Работа как внешней обработки: доступ к MCP_Config

Модуль формы обращается к общему модулю `MCP_Config` **не напрямую**, а через `МодульКонфигурацииMCP()` (поиск по имени + `Вычислить`). Причина: синтакс-контроль ВНЕШНЕЙ обработки идёт против основной конфигурации и модулей расширения не видит — прямая ссылка давала бы ошибку «Переменная не определена (MCP_Config)» ещё в конфигураторе, при полностью рабочем коде.

Следствия, о которых надо знать:

- обработка открывается и на базе без расширения MCP: в поле ошибки будет «общий модуль MCP_Config не найден…», дерево метаданных при этом строится, форму можно заполнять, а записанная политика применится после подключения расширения;
- нормализация имён типов и полей (регистр, пробелы, `_`, `-`, `.`, `ё`, суффикс `#2`) продублирована в форме функцией `НормКлючФормы` — копия `MCP_Config.НормализоватьКлючPrivacy`. При правке серверного правила **править обе**; расхождение ловит круговой порт `scripts/privacy_form_roundtrip_port.mjs`;
- у встроенной (не внешней) поставки этой проблемы нет, но код одинаков — отдельной ветки под встроенный вариант не требуется.

## 7. Отклонения от буквы ТЗ (зафиксированы кодовой сессией)

1. **Миграция R-12, префикс подчинённых** (§7.1): подчинённые справочники персон получают префикс «ИмяСправочника-» (`ПрефиксПоУмолчанию`), а НЕ «префикс физлиц»: одинаковый префикс у нескольких типов отклоняется валидатором уникальности (`ПроблемаПрефиксаPrivacy`), и запись-дубль «ФЛ-» молча не применилась бы — тихая утечка вместо материализации.
2. **Рубильник при записи** (§7.1, последний абзац): процедура записи констану `MCP_ServerConfig` НЕ трогает — §3.2 прямо запрещает форме её переписывать (риск повредить `limits`/`http`), а отсутствие ключа уже означает `Истина`, то есть запись `true` ничего бы не меняла.
3. **Колонка `ПсевдонимДоступен`** добавлена в левое дерево сверх А.3 — без неё условному оформлению не из чего вычислить «вид ссылочный».
