## 1. Основание (наблюдение на live 2026-07-16)

Запрос к `РегистрБухгалтерии.Хозрасчетный.ОстаткиИОбороты`:

```
ВЫБРАТЬ ПЕРВЫЕ 100 Ост.Период, Ост.СуммаРазвернутыйКонечныйОстатокДт
ИЗ РегистрБухгалтерии.Хозрасчетный.ОстаткиИОбороты(&Начало, &Конец, Месяц, ДвиженияИГраницыПериода, , , ) КАК Ост
```

отклонён с `error_code=validation_failed_before_run` и hint: «Поле 'СуммаРазвернутыйКонечныйОстатокДт'
не существует…», **при том что** список `available_fields` в этом же hint **содержал**
`СуммаРазвернутыйКонечныйОстатокДт`, а хвост hint предлагал его же как «Возможная замена». То есть
валидатор одновременно отклонял поле и объявлял его доступным/рекомендованным — само-противоречие.
Обычные поля (`СуммаКонечныйОстатокДт`) и развёрнутые поля `Остатки` (`СуммаРазвернутыйОстатокДт`) проходили.

## 2. Диагноз

Класс дефекта — **расхождение проверки принадлежности и списка `available_fields`**: проверка
(`ПолеЕстьВНаборе`) и генерация подсказок использовали разную нормализацию/сравнение имён, чем набор,
из которого строится `available_fields`. На текущей ветке набор для проверки и для показа — единый
(`ПолныйНаборПолейВиртуальнойТаблицыКэшированный`, F-07/F-08), поэтому точное само-противоречие
из отчёта на HEAD не воспроизводится прямым запросом; тем не менее сохранялись асимметрии
(проверка `ВРег` без `СокрЛП` против генераторного `ВРег ∘ СокрЛП`; подсказки на `СтрНачинаетсяС`
против точного равенства в проверке), способные проявить тот же симптом на пограничных входах.

## 3. Фикс (что тестируем)

1. **Единая нормализация** `НормализованныйКлючПоля = ВРег ∘ СокрЛП` (совпадает с
   `MCP_Metadata.ДобавитьПолеВНабор`). Через неё работают и `ПолеЕстьВНаборе`, и `ВариантыПохожихПолей`.
2. **Guard само-непротиворечивости** в `ВариантыПохожихПолей`: отклонённое поле не может быть предложено
   как замена самому себе (совпадение по нормализованному ключу исключается из кандидатов).
3. **Инвариант надмножества** для `ОстаткиИОбороты`: семейство `<Ресурс>Развернутый{Начальный|Конечный}Остаток{Дт|Кт}`
   присутствует в наборе (тот же генератор `ДобавитьСемействоОстаткаБухгалтерии`, что и для `Остатки`).
4. **Документация** приведена к реальному порядку сегментов: `Развернутый` идёт сразу после ресурса,
   перед `Начальный/Конечный` (`СуммаРазвернутыйКонечныйОстатокДт`), а не после (`…КонечныйРазвернутый…`).

## 4. Группы тест-кейсов

### TG-SC-A. Воспроизведение отчёта — развёрнутый конечный остаток проходит

| ID | Запрос (фрагмент) | Ожидаемое |
|---|---|---|
| DB-01 | `Ост.СуммаРазвернутыйКонечныйОстатокДт ИЗ …ОстаткиИОбороты(&Н,&К,Месяц,ДвиженияИГраницыПериода,,,) КАК Ост` | **не** `validation_failed_before_run`; запрос уходит на движок |
| DB-02 | `Ост.СуммаРазвернутыйНачальныйОстатокКт ИЗ …ОстаткиИОбороты(&Н,&К) КАК Ост` | **не** отказ pre-flight |

### TG-SC-B. Инвариант «advertised ⟹ accepted»

| ID | Проверка | Ожидаемое |
|---|---|---|
| SC-01 | адресовать **каждое** объявленное поле семейства `…Развернутый…Остаток{Дт/Кт}` из `common_fields` | ни одно не отклонено pre-flight |
| SC-02 | набор генератора для `ОстаткиИОбороты` ⊇ `{ СуммаРазвернутый{Начальный,Конечный}Остаток{Дт,Кт} }` | все четыре присутствуют |

### TG-SC-C. Guard: отклонённое поле не предлагается само себе

| ID | Запрос | Ожидаемое |
|---|---|---|
| SC-03 | заведомо отсутствующее `Ост.СуммаРазвернутыйКонечныйОстатокДтНесуществует` | `validation_failed_before_run`; `available_fields` **не** содержит отклонённое поле; «Возможная замена» **не** содержит его же |

### TG-SC-D. Регресс (не сломать)

- `Остатки` `СуммаРазвернутыйОстатокДт/Кт` — успех (базовый `regression.run_1c_query_developed_balance_fields_not_rejected`).
- Паритет `available_fields` ↔ `common_fields` (`parity.pre_flight_and_metadata_fields_match`) — зелёный.
- `ОборотыДтКт` без фантомов `СуммаОборотДт/Кт` (F5-fix) — зелёный.

## 5. Контрактные кейсы (`scripts/mcp_contract_test.mjs`)

- `regression.run_1c_query_balance_turnover_developed_fields_not_rejected` — DB-01.
- `invariant.pre_flight_never_rejects_advertised_vt_field` — SC-01.
- `invariant.pre_flight_rejection_never_suggests_rejected_field` — SC-03.
- `tool.vt_field_generator_authoritative_superset` — расширен: `ОстаткиИОбороты` ⊇ семейство развёрнутых (SC-02).

Запуск (3 режима обязательны):

```bash
MCP_URL="https://laba-1c.astondevs.ru/BUH_KORP/hs/mcp/rpc" MCP_BASIC="<user:pass>" \
node scripts/mcp_contract_test.mjs --all-response-modes --out reports/preflight_vt_selfconsistency.json --verbose
```

## 6. Матрица трассировки

| Порядок сегментов в документации | `MCP_Knowledge_1CQueryDocs.bsl`, `skills/.../virtual-tables.md`, `qa/golden_virtual_table_fields.md` | ревью + SC-02 |

## 7. Exit-критерии

1. TG-SC-A — DB-01/DB-02 не отклоняются pre-flight (движок вызван).
2. TG-SC-B — ни одно объявленное развёрнутое поле не отклонено; набор ⊇ семейства.
3. TG-SC-C — отклонённое поле отсутствует и в `available_fields`, и среди «Возможная замена».
4. TG-SC-D — базовый регресс (Остатки/ОборотыДтКт/паритет) зелёный.
5. Контрактный прогон зелёный в 3 режимах; артефакт приложен.

**Блокер релиза:** любой pre-flight-отказ на поле, присутствующем в `available_fields` того же ответа.
