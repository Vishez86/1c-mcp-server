# MCP tool с пагинацией для списка объектов метаданных 1С

Ниже пример реализации tool `metadata_list`, который возвращает список объектов метаданных 1С постранично.

Идея простая:

1. Первый запрос приходит без `cursor`.
2. Сервер отдаёт первую страницу.
3. В ответе сервер возвращает `nextCursor`.
4. Следующий запрос приходит уже с этим `cursor`.
5. Сервер отдаёт следующую страницу.
6. Когда страниц больше нет, сервер возвращает `nextCursor: null`.

---

## Общая идея tool

Tool называется:

```text
metadata_list
```

Клиент вызывает его так:

```json
{
  "limit": 100
}
```

Сервер отвечает:

```json
{
  "items": [...],
  "nextCursor": "100",
  "hasMore": true
}
```

Потом клиент вызывает тот же tool так:

```json
{
  "limit": 100,
  "cursor": "100"
}
```

И получает следующую страницу.

---

## Главное правило

`cursor` — это закладка.

Клиент не должен сам вычислять следующую страницу. Он просто берёт `nextCursor` из ответа и передаёт его обратно в следующий вызов.

То есть:

```text
Первый запрос:
  limit = 100

Ответ:
  items = объекты 1–100
  nextCursor = "100"

Второй запрос:
  limit = 100
  cursor = "100"

Ответ:
  items = объекты 101–200
  nextCursor = "200"
```

# Пример реализации на 1С

## Главная функция tool

```bsl
// Главная функция tool.
// Ее вызываешь из обработчика MCP tools/call, когда name = "metadata_list".
//
// Аргументы ожидаются такие:
// {
//   "limit": 100,
//   "cursor": "100"
// }

Функция ВыполнитьТулMetadataList(Аргументы) Экспорт

	Лимит = ПолучитьЧисловойАргумент(Аргументы, "limit", 100);

	// Защита от слишком больших ответов.
	Если Лимит < 1 Тогда
		Лимит = 100;
	КонецЕсли;

	Если Лимит > 500 Тогда
		Лимит = 500;
	КонецЕсли;

	Курсор = ПолучитьСтроковыйАргумент(Аргументы, "cursor", "");

	// В простом варианте cursor — это просто offset строкой: "0", "100", "200".
	Смещение = 0;

	Если НЕ ПустаяСтрока(Курсор) Тогда
		Попытка
			Смещение = Число(Курсор);
		Исключение
			Возврат СформироватьОшибкуТула("Некорректный cursor. Ожидается строка с числом, например ""100"".");
		КонецПопытки;
	КонецЕсли;

	Если Смещение < 0 Тогда
		Смещение = 0;
	КонецЕсли;

	ВсеОбъекты = ПолучитьВсеОбъектыМетаданных();

	// Очень важный момент:
	// сортируем всегда одинаково, чтобы страницы не прыгали.
	ВсеОбъекты.Сортировать("ПолноеИмя");

	Всего = ВсеОбъекты.Количество();

	Если Смещение > Всего Тогда
		Смещение = Всего;
	КонецЕсли;

	Элементы = Новый Массив;

	НачальныйИндекс = Смещение;
	КонечныйИндексНеВключительно = Мин(Смещение + Лимит, Всего);

	Для Индекс = НачальныйИндекс По КонечныйИндексНеВключительно - 1 Цикл

		СтрокаОбъекта = ВсеОбъекты[Индекс];

		Элемент = Новый Структура;
		Элемент.Вставить("kind", СтрокаОбъекта.Вид);
		Элемент.Вставить("kindRu", СтрокаОбъекта.ВидРус);
		Элемент.Вставить("name", СтрокаОбъекта.Имя);
		Элемент.Вставить("fullName", СтрокаОбъекта.ПолноеИмя);
		Элемент.Вставить("synonym", СтрокаОбъекта.Синоним);

		Элементы.Добавить(Элемент);

	КонецЦикла;

	ЕстьЕще = КонечныйИндексНеВключительно < Всего;

	Если ЕстьЕще Тогда
		СледующийКурсор = ЧислоВСтрокуДляКурсора(КонечныйИндексНеВключительно);
	Иначе
		СледующийКурсор = Неопределено;
	КонецЕсли;

	Данные = Новый Структура;
	Данные.Вставить("items", Элементы);
	Данные.Вставить("limit", Лимит);
	Данные.Вставить("offset", Смещение);
	Данные.Вставить("count", Элементы.Количество());
	Данные.Вставить("total", Всего);
	Данные.Вставить("hasMore", ЕстьЕще);
	Данные.Вставить("nextCursor", СледующийКурсор);

	Возврат СформироватьУспешныйРезультатТула(Данные);

КонецФункции
```

## Второй вызов

```json
{
  "limit": 3,
  "cursor": "3"
}
```

Сервер понимает:

```text
Первые 3 объекта уже отдали.
Теперь надо отдать объекты начиная с индекса 3.
```

И возвращает следующую пачку.

# Почему важна сортировка

Перед тем как резать список на страницы, его нужно сортировать:

```bsl
ВсеОбъекты.Сортировать("ПолноеИмя");
```

Иначе может случиться так:

```text
Первый запрос:
  отдали объекты 1–100

Второй запрос:
  список собрался в другом порядке
  отдали какие-то старые объекты повторно
  а какие-то пропустили
```

Сортировка делает список стабильным.

---

# Надо ли хранить состояние на сервере

В этом примере сервер ничего не хранит.

`cursor` — это просто offset:

```text
"100"
```

На каждом запросе сервер:

1. заново собирает список метаданных;
2. сортирует его;
3. берёт кусок начиная с offset;
4. возвращает новую страницу.

Для списка метаданных это хороший первый вариант: просто, понятно и надёжно.

---

# Что можно улучшить потом

Сейчас cursor простой:

```text
"100"
```

Позже можно сделать его непрозрачным, например хранить внутри JSON:

```json
{
  "offset": 100,
  "version": 1
}
```

И кодировать его в Base64.

Тогда клиенту будет приходить что-то вроде:

```text
eyJvZmZzZXQiOjEwMCwidmVyc2lvbiI6MX0=
```

Клиент всё равно не должен понимать, что внутри. Он просто передаёт этот cursor обратно серверу.

# Коротко

Пагинация работает так:

```text
1. Клиент вызывает tool без cursor.
2. Сервер отдаёт первую страницу и nextCursor.
3. Клиент вызывает tool с cursor = nextCursor.
4. Сервер отдаёт следующую страницу и новый nextCursor.
5. Так продолжается, пока hasMore не станет false.
```

Для первого рабочего варианта MCP-сервера на 1С этого достаточно.
