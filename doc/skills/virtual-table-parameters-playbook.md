# Виртуальные таблицы 1С: параметры вместо `ГДЕ`

## Жёсткое правило

Отборы по измерениям виртуальной таблицы задаются **только в её параметрах**. В `ГДЕ` остаются лишь условия по вычисленным полям, агрегатам (через `ИМЕЮЩИЕ`) и поля, которых конкретная виртуальная таблица не принимает по документированной и live-подтверждённой сигнатуре.

Нельзя переносить отбор в `ГДЕ` после первой ошибки. Перед этим обязательна диагностика:

1. сверить тип виртуальной таблицы и число позиций;
2. проверить порядок условий и пустые позиции `, ,`;
3. получить реальные виды субконто и передать их в предназначенный аргумент;
4. передать ссылочные значения строго типизированными параметрами;
5. выполнить минимальный запрос на live-базе и сравнить результат с базовым запросом;
6. только если все допустимые позиции подтверждённо отвергнуты, зафиксировать ошибку и причину в ТЗ.

## Шаблоны сигнатур

`[]` означает необязательную позицию. Пустая необязательная позиция сохраняется запятой, если используется следующий за ней аргумент.

| Семейство | Виртуальная таблица | Число позиций | Порядок аргументов |
|---|---|---:|---|
| Регистр сведений | `СрезПоследних`, `СрезПервых` | 2 | `Период, Условие` |
| Регистр накопления | `Остатки` | 2 | `Период, Условие` |
| Регистр накопления | `Обороты` | 4 | `НачалоПериода, КонецПериода, Периодичность, Условие` |
| Регистр накопления | `ОстаткиИОбороты` | 5 | `НачалоПериода, КонецПериода, Периодичность, МетодДополнения, Условие` |
| Регистр бухгалтерии | `Остатки` | 4 | `Период, УсловиеСчета, Субконто, Условие` |
| Регистр бухгалтерии | `Обороты` | 8 | `НачалоПериода, КонецПериода, Периодичность, УсловиеСчета, Субконто, Условие, УсловиеКорСчета, КорСубконто` |
| Регистр бухгалтерии | `ОстаткиИОбороты` | 7 | `НачалоПериода, КонецПериода, Периодичность, МетодДополнения, УсловиеСчета, Субконто, Условие` |
| Регистр бухгалтерии | `ОборотыДтКт` | 8 | `НачалоПериода, КонецПериода, Периодичность, УсловиеСчетаДт, СубконтоДт, УсловиеСчетаКт, СубконтоКт, Условие` |
| Регистр расчёта | все виртуальные таблицы | зависит от таблицы | Не угадывать: получить сигнатуру через метаданные/документацию и выполнить минимальный live-тест до применения. |

Статус: бухгалтерские `Остатки` (4 позиции) и `ОстаткиИОбороты` (7 позиций) подтверждены на текущей live-базе 24.07.2026. Остальные строки — шаблоны платформы, обязательные к live-подтверждению для конкретного регистра и версии платформы.

### Имя позиции — `Субконто`, не `ВидыСубконто`

Позиция называется `Субконто` (`СубконтоДт`/`СубконтоКт`/`КорСубконто` для сторон и корсчёта). `ВидыСубконто` — имя других сущностей, которые легко спутать с ней:

- `ПланСчетов.<Имя>.ВидыСубконто` — табличная часть плана счетов с настройкой аналитики счёта;
- `ПланВидовХарактеристик.ВидыСубконтоХозрасчетные` — сам план видов характеристик в типовых конфигурациях;
- `&ВидыСубконто` — обычное имя *параметра запроса*, значение которого передаётся в позицию `Субконто` (как в примерах ниже).

Позиции виртуальных таблиц в тексте запроса строго позиционны — именованных аргументов в языке запросов нет, поэтому имя влияет только на документацию и текст диагностик, но расхождение имён между источниками маскирует настоящую ошибку: в позицию `Субконто` передают *значения* субконто вместо массива их *видов*. Отбор по значению — только в последней позиции `Условие` (`Субконто1 = &Контрагент`).

## Проверенные бухгалтерские формы

```bsl
// Остатки: 4 позиции.
РегистрБухгалтерии.Хозрасчетный.Остатки(
    &Дата,
    Счет В ИЕРАРХИИ(&Счет),
    &ВидыСубконто,
    Субконто1 = &ЗначениеСубконто
) КАК Данные

// ОстаткиИОбороты: 7 позиций.
РегистрБухгалтерии.Хозрасчетный.ОстаткиИОбороты(
    &Начало,
    &Конец,
    , ,
    Счет В ИЕРАРХИИ(&Счет),
    &ВидыСубконто,
    Субконто1 = &ЗначениеСубконто
) КАК Данные
```

Для массива `&ВидыСубконто` порядок элементов определяет переиндексацию `Субконто1/2/3` в результате. Например, `[Контрагенты, Договоры]` задаёт `Субконто1 = Контрагент`, `Субконто2 = Договор`.

## Обязательная запись о проверке

Для каждого нового вида виртуальной таблицы сохранить в ТЗ:

- текст минимального запроса;
- параметры и их типы;
- фактическое число строк и время выполнения;
- исходный и итоговый вариант с объяснением каждой пустой позиции;
- подтверждение, что результат совпал с контрольным запросом.
