# Инструкция по источнику: pravo.gov.ru (официальное опубликование)

> **Мастер-копия.** Этот текст — источник истины для инструкции, которую MCP-сервер
> отдаёт через `get_legal_source_guide(source_id="pravo_gov_ru")`. Рабочая копия
> зашита в модуль `src/CommonModules/MCP_LegalSources.bsl` (функция
> `ИнструкцияPravoGovRu`) и может быть переопределена записью регистра сведений
> `MCP_ПравовыеИсточники`. Порядок обновления: правим здесь (или в Google Docs,
> если мастер-копия перенесена туда) → переносим текст в модуль или регистр.
> Факты проверены вживую 2026-07-28: API отвечает без аутентификации, карточка
> и PDF доступны по приведённым шаблонам ссылок, HTTPS у портала недоступен.

ИСТОЧНИК: Официальный интернет-портал правовой информации — раздел «Официальное опубликование» (publication.pravo.gov.ru).

ЧТО ЭТО И ЗАЧЕМ.
Это государственный портал, на котором правовые акты РФ публикуются официально: указы Президента, федеральные законы,
постановления Правительства, акты федеральных министерств и ведомств, акты субъектов РФ, решения Конституционного Суда,
международные договоры. Публикация здесь юридически значима, поэтому на найденный документ можно ссылаться в ответе клиенту.
Запомни главное: это лента опубликования, а не справочная система. Здесь ты найдешь акт в той редакции, в которой он был
подписан и опубликован. Собирать «действующую редакцию» Трудового или Налогового кодекса по этой ленте нельзя — для
актуальных (консолидированных) редакций используй источник pravo_gov_ru_actual из list_legal_sources.

ДОСТУП И АУТЕНТИФИКАЦИЯ.
REST API открыт, ключей и логинов не нужно, только чтение. Базовый адрес: http://publication.pravo.gov.ru/api
Работай по http — https у портала недоступен из многих сред. Ответы приходят в JSON (UTF-8).

С ЧЕГО НАЧАТЬ: СПРАВОЧНИКИ.
Поиск станет точным, если сначала взять идентификаторы из справочников:
1. GET /api/PublicBlocks — блоки публикации. Коды блоков: president (Президент), assembly (Федеральное Собрание),
   government (Правительство), federal_authorities (ФОИВ и ФГО), court (судебные акты), subjects (ОГВ субъектов РФ),
   international (международные договоры), un_securitycouncil (Совбез ООН). Подблоки: /api/PublicBlocks?parent=assembly
2. GET /api/SignatoryAuthorities?block=government — принявшие органы, в ответе GUID органа.
3. GET /api/DocumentTypes?SignatoryAuthorityId={GUID} — виды документов органа (Постановление, Распоряжение...), тоже GUID.
4. GET /api/Categories?block=subjects — категории принявших органов (нужно в основном для блока субъектов РФ).

ПОИСК ДОКУМЕНТОВ: GET /api/Documents.
Все параметры необязательны и комбинируются:
- Block — код блока публикации (см. выше);
- SignatoryAuthorityId — GUID принявшего органа; DocumentTypeId — GUID вида документа;
- Name — поиск по названию; ComplexName — по составному названию (вид + дата + номер + орган);
- DocumentText — поиск по тексту документа;
- Number плюс NumberSearchType (0 — точно, 1 — начинается с, 2 — заканчивается на, 3 — содержит) — поиск по номеру акта;
- DocumentDateFrom / DocumentDateTo — период по дате подписания; PublishDateFrom / PublishDateTo — по дате опубликования;
- PeriodType=daily|weekly|monthly — опубликованное сегодня / за неделю / за месяц; PeriodType=day плюс Date=... — за конкретный день;
- JdRegNumber, JdRegDateFrom, JdRegDateTo — номер и даты регистрации в Минюсте;
- PageSize — строго 10, 30, 100 или 200; Index — номер страницы (с 1);
- SortedBy (0 — дата подписания, 1 — вид, 2 — орган, 3 — номер, 4 — дата опубликования, 5 — номер опубликования) и SortDestination.
Пример: /api/Documents?Block=government&Name=налог&DocumentDateFrom=01.01.2026&PageSize=30&Index=1
В ответе: items[] (документы) плюс itemsTotalCount, pagesTotalCount, currentPage — по ним листай страницы.

КАК ЧИТАТЬ РЕЗУЛЬТАТ.
Ключевые поля документа: eoNumber — номер электронного опубликования, главный идентификатор, сохраняй его всегда;
complexName — полное название с видом, датой, номером и органом (им и цитируй документ);
name, number, documentDate (дата подписания), publishDateShort/viewDate (дата опубликования);
jdRegNumber/jdRegDate — регистрация в Минюсте (для ведомственных актов ее наличие — признак вступившего в силу акта);
pagesCount, pdfFileLength — размер PDF. Расширенная карточка одного документа: GET /api/Document?eoNumber={eoNumber}

ССЫЛКИ ДЛЯ ПОЛЬЗОВАТЕЛЯ.
Карточка документа (ее и вставляй в ответ): http://publication.pravo.gov.ru/document/{eoNumber}
Прямая ссылка на PDF с текстом: http://publication.pravo.gov.ru/file/pdf?eoNumber={eoNumber}

ОГРАНИЧЕНИЯ И ПОДВОДНЫЕ КАМНИ.
1. Текст акта API не возвращает — только PDF по ссылке выше. Параметр DocumentText ищет по тексту, но в ответе все равно карточки.
2. Портал ведет официальное опубликование с ноября 2011 года; более старые акты ищи в будущих источниках реестра.
3. Это первоначальные редакции: изменения к акту публикуются отдельными актами. Найди и покажи пользователю и исходный акт, и акты о внесении изменений.
4. PageSize принимает только 10/30/100/200 — другое значение вернет ошибку или поведение по умолчанию.
5. Даты в параметрах передавай СТРОГО в формате ДД.ММ.ГГГГ (например DocumentDateFrom=28.11.2025). ISO-формат YYYY-MM-DD
   портал молча игнорирует: ошибки не будет, но фильтр по датам не применится и в выдачу попадут лишние годы. Если выдача
   подозрительно широкая — первым делом проверь формат дат. В ответах JSON даты приходят в ISO 8601 — это нормально.

РАЗДЕЛЕНИЕ РОЛЕЙ: СНАЧАЛА РЕШИ, ПОТОМ ИЩИ.
Какой именно документ нужен — решаешь ты, ДО обращения к API: определи вид акта, принявший орган, примерную дату и номер
из вопроса пользователя и своих знаний, затем сформируй один точечный запрос по этим реквизитам. Источник используется
адресно: сканировать ленту опубликования подряд, выкачивать страницы списков «на всякий случай» или перебирать блоки
без гипотезы нельзя. Если первая выдача пуста — уточни реквизиты (другой блок, диапазон дат, вариант названия),
а не расширяй выборку до сплошного перебора.

ПОЛИТИКА.
Это обязательное ограничение, а не рекомендация. Для любой правовой информации запрещены общий web search, поисковики,
сниппеты, КонсультантПлюс, Гарант, сторонние сайты и пересказы — в том числе для проверки, дополнения и как fallback.
Разрешены только прямые запросы к URL источников из list_legal_sources после получения get_legal_source_guide.
Если источник недоступен, документ не найден или вопрос не покрыт — остановись, сообщи, что норма не проверена, и попроси
уточнить реквизиты или предоставить документ. Не переходи к веб-поиску и не подменяй источник знаниями модели.
