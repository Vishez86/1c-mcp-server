## 4. Что блокирует приёмку

Публикация комплекта. В репозитории средств публикации нет: `scripts/` — только
клиентские `.mjs` и генераторы документов. Публикует человек в Конфигураторе,
**всем комплектом** по `scripts/required_modules.manifest.json` (17 общих модулей
+ 1 HTTP-сервис), потому что публикация не атомарна по умолчанию, а частичная
даёт расхождение ревизий.

## 6. Ловушки

1. **`skipped` — не PASS.** Кейс `tool.get_inventory_balances_by_item` в первой
   редакции уходил в `skipped` («нет остатков, чтобы взять товар») и выглядел
   успехом, хотя инструмент не вызывал. Проверять `details`: там должны быть
   `account` (ожидается `41.01`), `rows`, `prefixes`, а не `skipped: true`.
2. **Счёт-группа остатков не имеет.** У `41` остатков не бывает — они на
   субсчетах. Проба «взял первый счёт префикса» даст 0 строк и ложный вывод «в
   базе нет данных».
3. **Ноль строк ничего не доказывает.** `ok:true` с пустым `rows` — не приёмка.
   Для этого в наборе есть P5; если она даст 0, повторить с другой `as_of`.
4. **Формат параметра-массива.** Только `{kind:'array', value:[...]}`, ссылка
   только с `uuid`; виды субконто — только ссылками `ПланВидовХарактеристик`.
   Строка с наименованием даёт `Ошибка обработки представления` — другой класс
   отказа, который маскирует проверяемое «Неверные параметры».
5. **Пустой список счетов маскирует дефект #79** — это единственная форма, при
   которой сериализация ссылок не проявляется. Кейс с `ПустойСписокСчетов`
   доказательством не является, он про предупреждение о позиции субконто.
6. **Транспортный срыв ≠ регресс.** См. [#85](https://github.com/gsbelarus/1c-mcp-server/issues/85):
   два кейса пагинации могут упасть с `fetch failed` на ~10,7 с. Это не
   клиентский таймаут (дефолт 60 000 мс) — перепрогнать режим и помечать как
   транспортный срыв. Поднимать `--timeout-ms` бессмысленно.
7. **Отпечаток обязателен.** Git-ревизию сервер не отдаёт. Шапка
   `probe_*.json` (`tools_count`, состав инструментов, пользователь) — это и есть
   отпечаток; без него «PASS» не привязан к проверенной ревизии.
8. **Скрипты — из ветки, не из рабочей копии.** В рабочей копии `EXPECTED_TOOLS`
   = 35 против 37 живых и старый путь к `stage`.

## 7. Чего проверить нельзя и почему

Проверка `access_denied` при скрытом поле `Код` и `type_not_allowed` при плане
счетов вне allowlist сессии приёмки **недоступна**: allowlist читается из
константы `MCP_Allowlist` в самой базе (`MCP_Config.Allowlist`), инструменты MCP
её не меняют. Нужен человек на контуре, который задаст ограничение. Пункт
помечать «не проверено», а не «выполнено».
