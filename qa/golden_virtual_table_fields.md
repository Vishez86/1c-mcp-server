# Golden-схемы полей виртуальных таблиц (pre-flight валидация)

Этот файл фиксирует **авторитетный набор-надмножество** полей виртуальных таблиц (ВТ),
который должен возвращать генератор `MCP_Metadata.ПолныйНаборПолейВиртуальнойТаблицы`.
Используется как ориентир при ревью и как опора для контрактных проверок
(`scripts/mcp_contract_test.mjs` → `tool.vt_field_generator_authoritative_superset`).

Связано с ТЗ `TZ_dev_preflight_vt_field_validation.md` (критерии приёмки 3, 4; риск R5).

## Принципы генерации

1. **Универсальность.** Имена строятся из реальных `Измерения/Ресурсы/Реквизиты/СтандартныеРеквизиты`
   регистра + правил суффиксов платформы. Нет привязки к конкретной конфигурации.
2. **Контракт надмножества.** Набор гарантированно ⊇ реальных колонок ВТ. Отклоняются только
   поля, которых в наборе нет → ложные отказы на валидных полях исключены (защита от регресса F4).
3. **Кастомные ресурсы.** Любой ресурс из `ОМД.Ресурсы` (в т.ч. нестандартный) разворачивается
   в полное семейство суффиксов (закрывает R1).
4. **Деградация.** Непокрытый вид регистра/ВТ → `supported=false` → pre-flight пропускает запрос
   на движок с warning (F-04), без отказа.

## РегистрБухгалтерии (корреспондентский, напр. Хозрасчетный)

Префиксы сумм `P` = реальные ресурсы ∪ { Сумма, ВалютнаяСумма, Количество } × { «», НУ, ПР, ВР }.
Балансовый префикс (для неразвёрнутого оборота в ДтКт) = ресурс со свойством метаданных
`Балансовый = Истина`; эвристика «ресурс с именем Сумма» осталась только деградацией на случай
недоступности свойства. `N` = `МаксКоличествоСубконто` (по умолчанию 3).

**Измерения зависят от вида ВТ** (issue #81): односторонние таблицы отдают измерения плоскими
именами; в двусторонних (`ОборотыДтКт`, `ДвиженияССубконто`) балансовое измерение — одно поле
`<Имя>`, небалансовое хранится по сторонам проводки и называется `<Имя>Дт`/`<Имя>Кт`
(плоского имени у небалансового измерения там НЕ существует). Ветвление — по свойству
метаданных `Балансовый` у измерения, без привязки к именам конфигурации; при недоступности
свойства добавляются все три формы (контракт надмножества, ложный отказ исключён).

| ВТ | Структурные поля | Ресурсные поля (для каждого префикса P) |
|---|---|---|
| `Остатки` | Счет, Субконто1..N, измерения | P+Остаток, P+ОстатокДт, P+ОстатокКт, P+РазвернутыйОстаток(Дт/Кт) |
| `Обороты` | Счет, Субконто1..N, измерения | P+Оборот, P+ОборотДт, P+ОборотКт |
| `ОборотыДтКт` | СчетДт, СчетКт, СубконтоДт1..N, СубконтоКт1..N, балансовые измерения плоско, небалансовые — <Имя>Дт/<Имя>Кт | для балансового P (Сумма): **только** P+Оборот; для небалансовых P (ВалютнаяСумма/Количество/НУ/ПР/ВР): **только** P+ОборотДт, P+ОборотКт (без общего P+Оборот и без P+ОборотДт/Кт у балансового) |
| `ОстаткиИОбороты` | Счет, Субконто1..N, Период, измерения | для корня `КОРЕНЬ`∈{НачальныйОстаток, КонечныйОстаток}: P+КОРЕНЬ, P+КОРЕНЬ+Дт, P+КОРЕНЬ+Кт, P+Развернутый+КОРЕНЬ, P+Развернутый+КОРЕНЬ+Дт, P+Развернутый+КОРЕНЬ+Кт; плюс P+Оборот, P+ОборотДт, P+ОборотКт |

> **Порядок сегментов развёрнутого остатка.** «Развернутый» вставляется **между префиксом-ресурсом и корнем**:
> `P + Развернутый + {Начальный|Конечный}Остаток + [Дт|Кт]` → напр. `СуммаРазвернутыйКонечныйОстатокДт`
> (тот же порядок, что у `Остатки`: `СуммаРазвернутыйОстатокДт`). Форма `…КонечныйРазвернутыйОстаток…`
> (Развернутый **после** Конечный) в 1С не существует и в набор не попадает.

| `ДвиженияССубконто` | Период, Регистратор, НомерСтроки, Активность, СчетДт, СчетКт, СубконтоДт1..N, СубконтоКт1..N, ВидСубконтоДт1..N, ВидСубконтоКт1..N, измерения по сторонам (как в ОборотыДтКт), реквизиты плоско | балансовый P: одно поле `P`; небалансовый P: `P`Дт, `P`Кт (это записи движений, суффикса Оборот/Остаток нет) |

`ДвиженияССубконто` строится ТОЛЬКО для регистра с корреспонденцией. Для регистра без
корреспонденции (`Счет`/`ВидДвижения` вместо сторон) состав живой пробой не доказан:
генератор возвращает `supported=false`, pre-flight пропускает запрос на движок с warning —
деградация без ложных отказов (принцип 4).

**Критические инварианты (проверяются в CI):**

- `Остатки` ⊇ { СуммаОстаток, СуммаОстатокДт, СуммаОстатокКт, СуммаРазвернутыйОстатокДт, СуммаРазвернутыйОстатокКт, КоличествоОстаток } и измерения Организация/Подразделение/Валюта.
- `ОборотыДтКт` ⊇ { СубконтоДт1, СубконтоКт1, СуммаОборот, СуммаПРОборотДт, СуммаПРОборотКт, ВалютнаяСуммаОборотДт, ВалютнаяСуммаОборотКт, КоличествоОборотДт, КоличествоОборотКт }.
- `ОборотыДтКт` **НЕ содержит** общих `Субконто1..N`; **НЕ содержит** неразвёрнутый `СуммаПРОборот`
  (у признаков учёта НУ/ПР/ВР, валютной и количественной суммы в ДтКт есть только Дт/Кт-варианты).
- `ОборотыДтКт` **НЕ содержит** `СуммаОборотДт`/`СуммаОборотКт` (F5-fix): у балансового ресурса «Сумма»
  сумма корреспонденции одна — есть только общий `СуммаОборот`, без Дт/Кт-разреза.
- `ОборотыДтКт` и `ДвиженияССубконто` **НЕ содержат** плоских имён небалансовых измерений
  (в БП: нет `Валюта`/`Подразделение`, есть `ВалютаДт`/`ВалютаКт`, `ПодразделениеДт`/`ПодразделениеКт`);
  балансовое измерение (в БП: `Организация`) — одним полем, без Дт/Кт (issue #81).
- `ДвиженияССубконто` ⊇ { Период, Регистратор, СчетДт, СчетКт, СубконтоДт1, ВидСубконтоДт1 } —
  единственная ВТ регистра с `Регистратор`; до issue #81 генератор возвращал для неё Ложь
  и pre-flight не работал вовсе.
- `ОстаткиИОбороты` ⊇ { СуммаРазвернутыйНачальныйОстатокДт, СуммаРазвернутыйНачальныйОстатокКт,
  СуммаРазвернутыйКонечныйОстатокДт, СуммаРазвернутыйКонечныйОстатокКт } — семейство развёрнутых остатков
  (report 2026-07-16). Порядок сегментов — `<Ресурс>Развернутый<Начальный|Конечный>Остаток<Дт|Кт>`.

**Инвариант само-непротиворечивости (advertised ⟹ accepted):**

- Любое поле, перечисленное в `available_fields` pre-flight-отказа, **обязано** проходить проверку
  `ПолеЕстьВНаборе` (не отклоняться). Проверка принадлежности и генератор `available_fields` используют
  один набор и одну нормализацию имени (`НормализованныйКлючПоля` = `ВРег ∘ СокрЛП`, как в
  `MCP_Metadata.ДобавитьПолеВНабор`). Отклонённое поле **никогда** не предлагается как «Возможная замена»
  самому себе. Контроль в CI: `invariant.pre_flight_never_rejects_advertised_vt_field`,
  `invariant.pre_flight_rejection_never_suggests_rejected_field`.

## РегистрНакопления

Для каждого ресурса `R` из `ОМД.Ресурсы`:

| ВТ | Поля |
|---|---|
| `Остатки` (для остаточных/«ОстаткиОбороты») | измерения, R+Остаток |
| `Обороты` | измерения, R+Оборот, R+Приход, R+Расход, служебные (Период/Регистратор/НомерСтроки/Активность) |
| `ОстаткиИОбороты` | измерения, Период, R+НачальныйОстаток, R+КонечныйОстаток, R+Оборот, R+Приход, R+Расход, служебные |

Устраняет F5 (раньше для регистров накопления `common_fields` был пуст → pre-flight не работал).

## РегистрСведений (срезы)

| ВТ | Поля |
|---|---|
| `СрезПоследних` / `СрезПервых` | измерения, ресурсы, реквизиты, Период, Регистратор, Активность, НомерСтроки |

## Поведение pre-flight

- Поле, адресованное напрямую алиасу источника-ВТ (`Алиас.Поле`, проверяется первый сегмент),
  которого нет в наборе → `error_code = validation_failed_before_run`, движок не вызывается.
- Разыменование (`Алиас.Измерение.Реквизит`) проверяет только первый сегмент (`Измерение`).
- Поля внутри скобок-параметров ВТ не валидируются (остаются за `vt_param_field_error`, F-06).
- `available_fields` в pre-flight отказе и `common_fields` из метаданных идентичны — один генератор (F-08).
