# TC-030 - get_database_passport_full

Инструмент: `get_database_passport_full`

Цель: проверить перепись метаданных счётчиками — что она называет масштаб конфигурации, не отдаёт имён объектов и честно объявляет, чего в переписи нет.

Карта создана 14.08.2026 вместе с инструментом (ТЗ `tz_passport_rebuild.md` v1.9.0).

## Предусловия

- MCP-сервер 1С развернут и подключен к LLM-чату.
- Пользователь в чате имеет права, достаточные для сценария.
- Значения в угловых скобках нужно заменить реальными данными целевой базы.

## Диалоговый сценарий

### Шаг 1

**Сообщение пользователя:**

> Насколько большая эта конфигурация? Сколько в ней справочников и регистров?

**Ожидаемое действие ассистента / MCP вызов:**

~~~json
{
  "tool": "get_database_passport_full",
  "arguments": {}
}
~~~

**Ожидаемый ответ ассистента:**

Ассистент называет счётчики по видам из `metadata_counts` — по каждому виду одно число, сколько объектов этого вида в конфигурации. Видов ровно 11, названия в множественном числе. Ассистент НЕ перечисляет имён объектов: их в ответе нет.

### Шаг 2

**Сообщение пользователя:**

> А сколько в базе отчётов?

**Ожидаемое действие ассистента / MCP вызов:**

Ассистент видит `Отчеты` в `excluded_kinds` и не выдаёт ноль за ответ. За числом отчётов идёт в перечисление:

~~~json
{
  "tool": "list_metadata_objects",
  "arguments": {"kinds": ["Отчет"], "limit": 1}
}
~~~

**Ожидаемый ответ ассистента:**

Ассистент говорит, что отчёты в перепись не входят по решению, и берёт их число из `total_estimated` перечисления.

**Провал шага:** ассистент сообщает, что отчётов в базе нет или ноль, приняв отсутствие вида в `metadata_counts` за пустоту.

### Шаг 3

**Сообщение пользователя:**

> Покажи, какие именно регистры сведений есть в базе.

**Ожидаемое действие ассистента / MCP вызов:**

~~~json
{
  "tool": "list_registers",
  "arguments": {"register_types": ["РегистрСведений"], "limit": 50}
}
~~~

**Ожидаемый ответ ассистента:**

Ассистент переводит вид из множественного числа в единственное (`РегистрыСведений` → `РегистрСведений`, карта есть в описании инструмента) и идёт за именами в перечисление. Повторный вызов переписи ради имён — провал: имён она не отдаёт вовсе.

## Дополнительная проверка

- **Перепись не меньше перечисления.** `metadata_counts.РегистрыНакопления` не может быть меньше `total_estimated` у `list_metadata_objects` с `kinds: ["РегистрНакопления"]`: перепись считает все объекты вида, а перечисление отдаёт только разрешённые политикой и правами. Равенство на контуре с пустым allowlist нормально; меньшее число — дефект.
- **Доступность не проверяется намеренно** (решение владельца 14.08): перепись отвечает про размер конфигурации, а не про права. Ответ обязан быть мгновенным — объекты не перебираются, считается только размер коллекции.
- **Ложного нуля нет.** Ноль в `metadata_counts` означает «объектов такого вида в базе нет» (например `РегистрыРасчета` в бухгалтерской конфигурации). Вид, который сервер посчитать не смог, обязан быть назван в `unsupported_kinds`, а не показан нулём. Поле `unsupported_kinds` присутствует всегда, даже пустым.
- **Имён объектов нет нигде**, включая `warnings`: предупреждения называют вид и число.
- **Данных не проверяет.** В ответе нет ни `has_data`, ни `total_entries`, ни периодов. Время ответа — единицы секунд без запросов к таблицам.

## Общие критерии приемки

- Ассистент не выдумывает имена объектов, полей, регистров или отчетов; при нехватке данных сначала использует обнаружение tools.
- Ответ ассистента кратко пересказывает результат для пользователя, а не вставляет полный JSON в чат.
- Если tool возвращает `truncated=true`, ассистент предлагает продолжить и использует `next_cursor` в следующем шаге.
- Ошибки доступа, валидации или отсутствия данных объясняются пользователю по структурированному MCP-ответу.
