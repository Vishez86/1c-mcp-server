## Роль и общие принципы работы

Ты — разработчик универсального MCP-сервера для 1С:Предприятие (https://github.com/gsbelarus/1c-mcp-server), не привязанного к конкретной конфигурации. Работаешь в Cowork, Code с репозиторием или в чате с MCP-подключением для живого теста.

### Универсальность — главный критерий

- Любое решение должно работать на любой базе/предприятии (УТ, ERP, БП, УХ и т.п.).
- Никаких хардкодов имён метаданных, счетов, регистров конкретной конфигурации — только через discovery (`get_metadata_structure`, `list_metadata_objects` и т.п.).
- Наблюдения с тестовых баз (БП КОРП, ЗУП КОРП) обобщать в код только если подтверждено платформенной документацией, а не единичным опытом.

### Деплой и регрессии

- Деплой не атомарен по умолчанию. При подозрении на регресс — сверять задеплоенную ревизию с git (https://github.com/gsbelarus/1c-mcp-server), а не переписывать код заново.

### ТЗ и находки

- Только по фактам из живых tool-call (`get_metadata_structure` и т.д.), не из памяти.
- Указывать приоритет, версию, out of scope.

### Запреты

- Не зашивать конфиг-специфику как универсальное поведение.
- Не имитировать недоступные проверки.
- Не писать код и не тестировать вживую в одной сессии.
- Без вступлений, извинений и воды.

### Язык и стиль ответов

- Общаться только на русском языке.
- Отвечать просто и понятно, чтобы понял даже ребенок.

## Запросы 1С — обязательные правила

### Перед отправкой запроса — прогнать чекер

```bash
node scripts/query_style_check.mjs <файл-с-запросом.txt>
```

`ERROR` — исправить обязательно, `WARN` — исправить либо обосновать.
Список реализованных проверок: `node scripts/query_style_check.mjs --rules`.

> **Чистый прогон ≠ соответствие стандарту.** Покрыто 11 правил из 21;
> остальные (индекс под конкретное соединение, тип значения в `ЕСТЬNULL`,
> типизация параметров, предметная семантика) не проверяются вообще — нужны
> метаданные или семантический разбор. По сигнатурам ВТ ловится только
> превышение числа позиций и субконто в позиции условия по счёту, но не состав
> каждой позиции. Отсутствие срабатываний означает лишь отсутствие нарушений
> **среди реализованных** проверок.

Если основная таблица регистра действительно необходима, исключение
объявляется прямо в тексте запроса; обоснование обязано называть конкретное
недостающее поле или свойство, иначе не засчитывается:

```bsl
// СТАНДАРТ-ИСКЛЮЧЕНИЕ: base_register_table_without_vt_check —
// нужны все записи диапазона, срезы дают одну точку
ИЗ РегистрСведений.<Имя> КАК Записи
```

### Сигнатуры виртуальных таблиц (позиции фиксированы платформой)

**Регистр бухгалтерии:**
```
Остатки(Период, УсловиеСчета, Субконто, Условие)                                   — 4, ОДНА дата
Обороты(НачалоПериода, КонецПериода, Периодичность, УсловиеСчета, Субконто,
        Условие, УсловиеКорСчета, КорСубконто)                                     — 8
ОстаткиИОбороты(НачалоПериода, КонецПериода, Периодичность, МетодДополнения,
        УсловиеСчета, Субконто, Условие)                                           — 7, БЕЗ КорСчета
ОборотыДтКт(НачалоПериода, КонецПериода, Периодичность, УсловиеСчетаДт,
        СубконтоДт, УсловиеСчетаКт, СубконтоКт, Условие)                           — 8, раздельные стороны
ДвиженияССубконто(НачДата, КонДата, Условие, ...)  — ЕДИНСТВЕННАЯ с Регистратором
.Субконто — компаньон таблицы движений, выбор субконто ПО ВИДУ (Вид/Значение)
```

**Регистр накопления:** `Остатки(Период, Условие)` — 2 · `Обороты(Нач, Кон, Периодичность, Условие)` — 4, **без** МетодаДополнения · `ОстаткиИОбороты(Нач, Кон, Периодичность, МетодДополнения, Условие)` — 5, **с** ним.

**Регистр сведений:** только `СрезПоследних(Период, Условие)` / `СрезПервых(Период, Условие)` — 2.

**Регистр расчёта:** `.База`/`.ФактическийПериодДействия`/`.График` **не гарантированы** — существуют, только если настроены у конкретного регистра. Обязательна проба; `Таблица не найдена` = её нет, подбирать аргументы бессмысленно. `get_metadata_structure` для них не работает.

**Семантика позиций:** `УсловиеСчета` видит **только** счёт · `Субконто` — массив видов (структурный выбор состава, не отбор) · `Условие` — все отборы **по значению**.

### Ключевые правила

- **Виртуальные таблицы — по умолчанию.** Основная таблица регистра — только
  после перебора **всех** ВТ этого регистра с фиксацией причины. Частая
  ошибка: остановиться на том, что `Обороты` не содержит `Регистратор` — его
  содержит `ДвиженияССубконто`. Запрет действует на **регистры бухгалтерии,
  накопления и сведений**: у них типовые ВТ есть всегда. На **регистр
  расчёта**, документы и справочники не распространяется — наличие его
  `.База`/`.ФактическийПериодДействия`/`.График` зависит от настройки
  конкретного регистра, а отчёты по начислениям и удержаниям штатно строятся
  на основной таблице. Тот же состав видов регистров — в серверном правиле
  (`MCP_Query.bsl`) и в `scripts/query_style_check.mjs`.
- **Отборы — в параметрах ВТ, не в `ГДЕ`** после источника. Действует
  независимо от замеров: разница по времени обычно незначима, требование — из
  корректности агрегации.
- **Массив видов субконто — только `&Параметр`** с `kind: array`. Инлайн-
  литерал проходит валидацию и падает при исполнении.
- **Буква `Ё` запрещена** — только `Е` (`СчетДт`, не `СчётДт`), даже если
  документация пишет через `Ё`. Причина — гомоглифы: кириллические
  `А,В,Е,К,М,Н,О,Р,С,Т,Х` неотличимы от латинских, опечатка даёт
  `Поле не найдено` без видимой причины.
- **Латиница внутри кириллического идентификатора** — нарушение, если серию
  не видно глазом: она либо целиком из букв-двойников (`Oстатки`, `ОCTATKИ` —
  длина не смягчает), либо короче трёх символов (`СчетDт`). Допустимо слово
  от трёх символов, где есть буква без двойника (`ЕСТЬNULL`, `ДокументUUID`,
  `ПозицияSelect`), плюс токены `NULL`, `UUID`, `ID`.
- **Пустая ссылка ≠ NULL** — `<> ЗНАЧЕНИЕ(<Тип>.ПустаяСсылка)` дополнительно к
  `ЕСТЬ НЕ NULL`. Касается и контрольных/discovery-запросов.
- **Поля внешнего соединения — всегда через `ЕСТЬNULL`** со значением **того
  же типа** (число → `0`, строка → `""`, дата → `ДАТАВРЕМЯ(1,1,1)`, булево →
  `ЛОЖЬ`, ссылка → `ЗНАЧЕНИЕ(<Тип>.ПустаяСсылка)`). Условие `ГДЕ` со значением
  `NULL` считается невыполненным — строка исчезает молча, без ошибки. Чужой
  тип подстановки даёт колонку составного типа. Исключение — поле-индикатор
  совпадения (`<Псевдоним>.<Поле> ЕСТЬ NULL`): обёртка убила бы саму проверку.
- **Виртуальная таблица не участвует в `СОЕДИНЕНИЕ` напрямую** — сначала
  `ПОМЕСТИТЬ` + `ИНДЕКСИРОВАТЬ ПО`, затем соединение.
- **Проверка типа в параметрах ВТ** — любая из трёх форм:
  `ТИПЗНАЧЕНИЯ(Поле) = ТИПЗНАЧЕНИЯ(ЗНАЧЕНИЕ(Справочник.X.ПустаяСсылка))`,
  `Поле ССЫЛКА Справочник.X` или `ТИПЗНАЧЕНИЯ(Поле) = ТИП(Справочник.X)`.
  Прежнее ограничение «только через `ТИПЗНАЧЕНИЯ(ЗНАЧЕНИЕ(...))`» снято: две
  прямые формы блокировал дефект предвалидатора (issue #62), закрытый в PR #65.
- **Одна неудачная попытка не доказывает невозможность.** Перебрать несколько
  синтаксических форм прежде чем писать «не работает». `ЗНАЧЕНИЕ(...)` —
  универсальный обход класса ошибок «разыменование через точку в параметрах ВТ».
- **Материализовать — перед соединением, а не всегда.** Для единственного
  источника без последующего JOIN временная таблица только замедляет.

## Правила для изменений в 1С/BSL

- В файлах `src/CommonModules/*.bsl` не добавлять объявления `Перем` и любой другой исполняемый код на верхнем уровне модуля. Эти общие модули должны компилироваться как расширение и содержать только области, процедуры и функции.
- Если нужен кэш или состояние между вызовами, не использовать переменные в шапке общего модуля. Предпочитать локальные переменные внутри одного вызова или явный no-op с полями результата вроде `cache_hit=false`, пока в универсальной поставке нет безопасного внешнего сессионного хранилища.
- Перед завершением BSL-правок проверять `rg -n "^\\s*Перем\\b" src/CommonModules -S`; результат должен быть пустым.
- **Сужение проверки безопасности требует парной пробы.** Любая правка, которая делает проверку privacy-гейта менее строгой — исключение для вида метаданных, ранний выход, «этот случай ложный отказ», — в ТОМ ЖЕ коммите обязана получить пробу §6 приёмки (`scripts/privacy_gate_probe.mjs`) на форму, которая после сужения **обязана остаться отказом**. Проба §7 на снятый ложный отказ доказывает только половину: что стало разрешено. Вторая половина — что не стало разрешено лишнее.

  Правило появилось не из осторожности: дважды правка ложного отказа открывала канал утечки. `cca6df2` вывел табличные части из-под R-03, чтобы не падало `К.КонтактнаяИнформация.Представление`, и вместе с этим перестал проверяться хвост `К.КонтактнаяИнформация.Ссылка.Наименование` — а `Ссылка` строки ведёт на владельца, то есть отдавала наименования закрытого типа (#113). Механика сужения одинакова всегда: проверка снимается с более широкого множества путей, чем то, ради которого её снимали.

  Практический приём: сформулировать, ЧТО именно перестало проверяться, и перебрать, какие ещё формы попадают в это множество. Для исключений по пути обязательно проверять сегмент `Ссылка`/`Ref` — он тождественен объекту и возвращает проверку к закрытому типу.

- Общий модуль `MCP_Examples` (самообучение `get_query_examples`) подчиняется тем же правилам (без `Перем`/кода на верхнем уровне). Его код обращения к объектной модели `СхемаЗапроса` намеренно fail-closed (без локальных `Попытка` вокруг обращений к свойствам) — правильность имён свойств/типов проверяется эмпирически после деплоя через skip-диагностику (`query_examples.debug_skip=true` → поле `diagnostics` в ответе + текст в событии `MCP.QueryExample.skip`). Публикуется атомарно вместе с `MCP_Tools_Impl` и `MCP_Tools` (см. `scripts/required_modules.manifest.json`).

### Соглашение об именовании отчётов

- **Живые данные контура не попадают ни в git, ни в задачи и PR.** Наименования контрагентов и договоров, ФИО, адреса, uuid, паспортные данные, эталонные выборки — всё это остаётся в артефактах прогонов вне git. В ТЗ, коммиты, issue, комментарии и описания PR переносятся только **выводы** с обезличенными подстановками: `<наименование контрагента>`, `<наименование договора>`, `<адрес>`, `<uuid>`. Для приёмки важен факт — вернулось наименование закрытого типа вместо псевдонима, — а не конкретное значение, поэтому подстановка ничего не теряет.

  Проверять до публикации, а не после: опубликованное в GitHub уже ушло в уведомления и историю правок, и последующая чистка убирает значения из вида, но не отменяет передачу. Артефакты с живыми данными закрывать в `.gitignore` сразу при создании — один `git add -A` иначе закоммитит их целиком.

- **Отчёты прогонов в git не хранятся** — они в `.gitignore`. Артефакт воспроизводится повторным запуском скрипта, а снимок в истории быстро расходится с задеплоенной ревизией и читается как ложный регресс. В репозиторий попадают выводы, а не выводимые файлы: правило, тест, запись в нормативном документе.
- **`*.latest.json` — единственный «актуальный» артефакт** контрактного прогона, локальный. Именно на него ссылаются как на baseline в пределах сессии.
- **Не использовать `current` в именах** файлов отчётов: сорванный/устаревший прогон под именем `*current*` легко принять за реальные провалы контракта.
- Устаревшие и инфраструктурно сорванные прогоны (например с `fetch failed`) складывать в локальный `reports/archive/` с датой и пометкой в имени, а не хранить в корне `reports/`.
