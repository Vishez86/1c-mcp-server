## Правила для изменений в 1С/BSL

- В файлах `src/CommonModules/*.bsl` не добавлять объявления `Перем` и любой другой исполняемый код на верхнем уровне модуля. Эти общие модули должны компилироваться как расширение и содержать только области, процедуры и функции.
- Если нужен кэш или состояние между вызовами, не использовать переменные в шапке общего модуля. Предпочитать локальные переменные внутри одного вызова или явный no-op с полями результата вроде `cache_hit=false`, пока в универсальной поставке нет безопасного внешнего сессионного хранилища.
- Перед завершением BSL-правок проверять `rg -n "^\\s*Перем\\b" src/CommonModules -S`; результат должен быть пустым.

## Contract tests для 1c-korp MCP

- Основной автотест находится в `scripts/mcp_contract_test.mjs`; по умолчанию он целится в `https://laba-1c.astondevs.ru/BUH_KORP/hs/mcp/rpc`.
- Обычный прогон: `node scripts\mcp_contract_test.mjs --out reports\mcp_contract_report.1c-korp.latest.json`.
- После изменений формата tool result прогонять все три режима: `node scripts\mcp_contract_test.mjs --all-response-modes --out reports\mcp_contract_report.1c-korp.latest.json`. Скрипт создаст агрегатный отчет и отдельные `*.text_only.json`, `*.structured_only.json`, `*.both.json`.
- Если менялись BSL-файлы расширения, полный прогон по живому `1c-korp` имеет смысл делать после деплоя обновленного расширения в 1С; до деплоя endpoint будет отвечать старым кодом.
