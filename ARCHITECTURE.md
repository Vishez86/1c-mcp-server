# Архитектура Universal 1C MCP Server

## Общая схема

```
        +-------------------------+
        |       MCP Client        |
        | (Claude / Codex / ...) |
        +-----------+-------------+
                    | HTTPS + MCP Streamable HTTP
                    v
        +-------------------------+
        |   HTTP-сервис MCP        |  <- src/HTTPServices/MCP_HTTPService.bsl
        +-----------+-------------+
                    |
                    v
        +-------------------------+
        |   MCP_JSONRPC dispatch  |  <- routing initialize / tools/list / tools/call
        +-----------+-------------+
                    |
        +-----------v-------------+
        |   MCP_Security gate     |  <- allowlist, права, лимиты
        +-----------+-------------+
                    |
        +-----------v-------------+      +---------------+
        |   MCP_Tools dispatch    |----->| MCP_Tools_Impl|  (37 read-only tools)
        +-----------+-------------+      +-------+-------+
                    |                            |
                    v                            v
        +-----------+--------+    +--------------+-----------+
        |   MCP_Audit log    |    |   MCP_Metadata / Query / |
        +--------------------+    |   Registers / Reports /  |
                                  |   History / Values /     |
                                  |   Knowledge /            |
                                  |   LegalSources           |
                                  +--------------------------+
                                                |
                                                v
                                  +--------------------------+
                                  |     1С:Предприятие        |
                                  |  (БД, метаданные, СКД)   |
                                  +--------------------------+
```

## Модули

### `MCP_HTTPService`
Точка входа Streamable HTTP. Принимает POST с JSON-RPC, передаёт тело в `MCP_JSONRPC.ОбработатьЗапрос`, возвращает JSON для request-вызовов и `202 Accepted` без тела для notifications/responses. GET и DELETE возвращают `405 Method Not Allowed`, потому что сервер stateless и не открывает отдельный SSE-канал.

### `MCP_JSONRPC`
Реализует JSON-RPC 2.0 и MCP-методы:
- `initialize` — рукопожатие, возврат `protocolVersion`, `capabilities`, `serverInfo`.
- `tools/list` — список tools из `MCP_Tools`.
- `tools/call` — вызов tool, единый формат результата.
- `resources/list` / `resources/read` — статичные MCP resources (опционально).
- `ping`.

### `MCP_Tools`
Каталог всех 37 tools: описания (`name`, `title`, `description`, `inputSchema`).
Dispatcher `Выполнить(ИмяТула, Аргументы, Контекст)` → передача в реализацию.

### `MCP_Tools_Impl`
Бизнес-логика всех 37 tools. Каждая функция:
1. Валидирует аргументы.
2. Запрашивает у `MCP_Security` разрешение на тип/поле.
3. Использует `MCP_Metadata`, `MCP_Query`, `MCP_Registers`, `MCP_Reports`, `MCP_History`.
4. Кодирует результат через `MCP_Values`.
5. Возвращает структуру `{ ok, ... }`.

### `MCP_Security`
- Загрузка allowlist/denylist.
- Проверки: `ТипРазрешен(Тип)`, `ПолеРазрешено(Тип, Поле)`, `ToolРазрешен(ИмяТула, Контекст)`.
- Маскирование чувствительных полей.
- Проверка лимитов: max_limit, max_query_rows, timeouts и т.д.

### `MCP_Audit`
Запись в журнал регистрации событий `MCP.<name>.success / .error` с `correlation_id`, безопасными аргументами, метаданными результата и `duration_ms` (без больших payload).
Для каждого HTTP-вызова `/rpc` пишется `MCP.http_request`: `kind`, `http_method`, `http_status`, `duration_ms`, `outcome`, `user`, `timestamp` и для POST `request_chars`. Тела запросов, тела ответов и заголовки, включая `Authorization`, не записываются. Успешные запросы, notifications (`202`), CORS preflight (`204`) и штатные `405` — «Информация»; отклонённые Origin/версия протокола и пустое тело — «Предупреждение»; внутренние ошибки (`500+`) — «Ошибка».

### `MCP_Values`
Кодирование значений 1С в JSON-совместимые структуры:
- Ссылка → `ObjectRef { type, uuid, presentation, navigation_url }`.
- ПеречислениеСсылка → `EnumRef`.
- Дата → ISO 8601.
- ХранилищеЗначения → метаданные без содержимого.
- Двоичные данные → пропускаются, если не разрешены.
- ТаблицаЗначений → `{ columns, rows }`.

Также реализует обратное преобразование `QueryParameterValue` → значение 1С.

### `MCP_Metadata`
- Обход всех видов метаданных (Справочники, Документы, Регистры, и т.д.).
- Поддержка `query_table`, `supports_ref`, `hierarchical`, `register_schema`.

### `MCP_Query`
- Безопасное выполнение запросов 1С.
- Валидация запроса (`validate_1c_query`): таблицы из allowlist, разрешённый список конструкций, наличие лимита, ограничение времени.
- Параметризация через `Запрос.УстановитьПараметр`.
- Возвращает `query_guidance` из `MCP_Knowledge`, если запрос содержит рискованные или сложные конструкции.

### `MCP_Knowledge`
- Встроенная база знаний для LLM по `doc/skills`: синтаксис запросов, функции, временные таблицы, составные типы, субконто и оптимизация.
- Отдаётся через tool `get_1c_query_guidance` и resources `1c://knowledge/query/*`.
- Не зависит от структуры конкретной базы: все прикладные имена должны браться через metadata tools.

### `MCP_LegalSources`
Реестр правовых источников и инструкции по работе с ними (tools `list_legal_sources`, `get_legal_source_guide`).
- Обязательная политика: для любой правовой информации запрещены общий web search, поисковики, сниппеты, не включённые в реестр правовые сайты и консультационные порталы — в том числе для перепроверки и как fallback. Разрешён только прямой доступ к URL источника из реестра после `get_legal_source_guide`; какой документ нужен — модель решает до обращения к источнику (точечные запросы, без сканирования).
- Fail-closed: если разрешённый источник недоступен, документ не найден или вопрос не покрыт, модель сообщает, что норма не проверена, и просит уточнение/документ; переходить к веб-поиску или заменять источник знаниями модели нельзя.
- Runtime-доставка правила: `initialize.instructions` → `tools/list.server_hints` → описания обоих tools → машинно-читаемый `policy` каждого результата → текст инструкции. `ARCHITECTURE.md` не является единственным каналом и сам по себе не считается runtime-инструкцией.
- Граница гарантии: MCP-сервер может передать обязательную политику клиенту, но не может физически заблокировать отдельный web-tool клиента. Для технической гарантии оркестратор клиента должен отключить общий веб-поиск в правовом маршруте или применить allowlist URL из `get_legal_source_guide`.
- Реестр зашит в модуль (первый источник — `pravo_gov_ru`, publication.pravo.gov.ru с открытым API); сам модуль в сеть не ходит — HTTP-запросы к источнику выполняет агент на своей стороне по инструкции.
- Опциональное переопределение без обновления расширения: регистр сведений `MCP_ПравовыеИсточники` (см. `INSTALL.md`, шаг 7a); ошибки чтения регистра не фатальны.
- Мастер-копия инструкций: `doc/legal_sources/*.md` (переносится в Google Docs), рабочая копия — в модуле/регистре.

### `MCP_Registers`
- Обёртки над виртуальными таблицами регистров: `СрезПервых`, `СрезПоследних`, `Остатки`, `Обороты`, `ОстаткиИОбороты`.
- Поиск движений документа: запрос к каждому разрешённому регистру с фильтром по `Регистратор`.

### `MCP_Reports`
- Список отчётов и вариантов (СКД).
- Получение параметров СКД.
- Выполнение СКД через `ПроцессорКомпоновкиДанных`.
- Адаптер для не-СКД отчётов (заглушка `supported=false`).

### `MCP_History`
- Версии объектов через подсистему версионирования (если включена).
- Журнал регистрации (`ВыгрузитьЖурналРегистрации`).
- Регистр истории статусов (для типовых конфигураций).

### `MCP_Examples`
Самообучение на успешных `run_1c_query` (tool `get_query_examples`). Хранилище — только журнал регистрации (нулевой footprint, собственных объектов данных нет). Feature opt-in (`MCP_Config.QueryExamplesВключены`), классификация **operational metadata write**.
- **Запись** (`ЗаписатьПример`, вызывается хуком в `MCP_Tools_Impl.Run1CQuery` после успешного запроса и только при пустом `cursor`): обезличивание — срез комментариев, замена литералов/имён параметров плейсхолдерами (`&Строка/&Дата/&Число/&Парам`), затем `СхемаЗапроса` для сбора полных имён таблиц (§6.4) и канонизации псевдонимов источников/колонок и имён ВТ (`Т1`/`Поле1`/`ВТ1`, §6.5), регенерация текста и `SHA-256`. Результат — событие `MCP.QueryExample` (уровень «Информация») с JSON v1. Любой сбой стадии `СхемаЗапроса` → пример не пишется (fail-closed, без частично обезличенного текста); диагностика — событие `MCP.QueryExample.skip`. Инвариант полноты: канонизация покрывает позицию `ИЗ` (и вложенные запросы-источники `ИЗ`); если в итоговом skeleton остаётся необойдённый `ВЫБРАТЬ` (подзапрос в списке `ВЫБРАТЬ`/`ГДЕ`), пример консервативно не пишется — иначе идентификаторы/таблицы такого подзапроса утекли бы мимо канонизации и фильтрации по правам.
- **Чтение** (`ПолучитьПримеры`): `ВыгрузитьЖурналРегистрации` по событию под текущим пользователем (право `ПросмотрЖурналаРегистрации`), группировка по `skeleton_hash`, ранжирование (совпадение версии конфигурации → `uses` → `last_used`), фильтрация выдачи по правам читателя (`MCP_Security.ДоступКТипу` для каждой таблицы шаблона). Дедупликация — при чтении, не при записи.
- Поток: запись-события (много сессий) → чтение-агрегация (новая сессия получает 3–5 проверенных скелетов).

### `MCP_Errors`
- Стандартные коды ошибок (см. раздел 9 спецификации).
- Преобразование `ОписаниеОшибки()` в `{ code, message, details, correlation_id }`.

### `MCP_Config`
- Загрузка allowlist из константы / регистра / файла.
- Лимиты по умолчанию (см. раздел 5 спецификации).
- Runtime-настройки `MCP_ServerConfig`, включая `privacy.masked_fields`, `privacy.organization_aliases`, `privacy.person_aliases`, а также адресные `privacy.type_aliases` и `privacy.type_field_masks` (по конкретному полному имени типа, включая регистры) для маскирования перед выдачей MCP-клиенту.
- Публичная privacy-информация для LLM: активность маскирования, список полей, псевдонимы организаций/физлиц/сотрудников и настроенных типов, маски полей по типам, `config_warnings` о непринятых записях и инструкция не пытаться обходить политику.

## Поток выполнения tools/call

```
1. HTTP-сервис принимает POST на `/hs/mcp/rpc`.
2. JSON-RPC dispatcher разбирает request.
3. Проверка auth.
4. tools/call → MCP_Tools.Выполнить:
   4.1. Проверка существования tool.
   4.2. JSON Schema валидация arguments.
   4.3. Security gate: ToolРазрешен.
   4.4. Вызов реализации из MCP_Tools_Impl.
   4.5. Реализация делегирует в Metadata / Query / ... .
   4.6. Результат кодируется в JSON через MCP_Values.
   4.7. MCP_Tools добавляет `auth_context` с текущим пользователем 1С, базой, версией конфигурации, `identity_key` и `cache_policy.cacheable=false`.
   4.8. MCP_Tools добавляет privacy-информацию, если маскирование или псевдонимы сущностей активны, а также при выключенном маскировании, когда есть `config_warnings` о непринятых privacy-записях.
   4.9. MCP_Security маскирует поля из privacy.masked_fields, заменяет названия организаций и ФИО физлиц/сотрудников стабильными псевдонимами, а также применяет privacy.type_aliases и privacy.type_field_masks по типу текущего объекта (ссылка, вложенный `ref` или полное имя регистра), сохраняя UUID/type/navigation_url для открытия объекта в 1С.
   4.10. Audit запись по уже замаскированному результату.
   4.11. Унифицированный MCP tool result с учётом `response.tool_result_mode`: `text_only` отдаёт полный JSON только в `content[].text`; `structured_only` отдаёт JSON в `structuredContent`; `both` отдаёт оба канала.
5. JSON-RPC dispatcher формирует response.
6. HTTP-сервис отдаёт ответ.
```

## Ошибки прав доступа

Все операции читают данные в текущем сеансе 1С, поэтому платформенные роли, RLS и прикладные проверки могут отказать отдельной учетной записи даже при разрешенном allowlist. Такие сбои нормализуются в MCP tool error: `isError=true`, `ok=false`, `error.code=access_denied`, `authorization.reason_code=1c_access_denied` и `authorization.retry_policy=do_not_retry_same_request_without_reauth_or_permission_change`. В `text_only` эти поля находятся в JSON внутри `content[].text`; в `structured_only` и `both` — в `structuredContent`.

MCP-ограничения сервера тоже отражаются в `authorization`: `mcp_type_not_allowed`, `mcp_field_not_allowed`, `mcp_tool_not_allowed`. Для совместимости с промежуточными proxy, которые не передают `structuredContent`, используйте `response.tool_result_mode=text_only` или `both`.

В `tools/list` общий `outputSchema` объявляется только для режимов `structured_only` и `both`. В `text_only` сервер не объявляет `outputSchema`, чтобы клиенты не ожидали `structuredContent`.

`tools/list`, описания tools и `get_current_user_context` явно предупреждают LLM: сведения о доступе зависят от текущей учетной записи 1С и не кэшируются между перелогинами.

## Read-only гарантии

- В коде сервера нет операций `Записать`, `Удалить`, `Провести`, `ОтменитьПроведение`, `НачатьТранзакцию` (кроме `НачатьТранзакцию` через `Запрос` для read-only снепшотов — не применяется).
- Сервисный пользователь 1С имеет только права на чтение нужных объектов.
- Постоянные данные остаются read-only: запрещены `ИЗМЕНИТЬ`, `ДЛЯ ИЗМЕНЕНИЯ`, SQL-like `UPDATE/INSERT/DELETE/DROP` и обход прав.
- Временные таблицы разрешены внутри пакетного запроса: `ПОМЕСТИТЬ`, `ИНДЕКСИРОВАТЬ ПО`, `УНИЧТОЖИТЬ`. Они считаются рабочей областью выполнения запроса и не дают права менять прикладные данные.
- `run_1c_query` всегда применяет server-side лимит (`ПЕРВЫЕ N` / `TOP N`) и не позволяет клиенту обойти allowlist.

## Пагинация

Все списковые tools поддерживают `cursor`/`next_cursor` по схеме из `mcp_1c_metadata_pagination.md`:

- `cursor` — opaque строка (offset или Base64-JSON).
- `next_cursor = null` означает конец данных.
- Список сортируется детерминированно (например, по `ПолноеИмя`).

## Лимиты по умолчанию

| Параметр | Значение |
|---|---:|
| max_limit | 1000 |
| max_query_rows | 1000 |
| max_report_rows | 5000 |
| max_tabular_section_rows | 100 |
| max_register_rows | 1000 |
| query_timeout_seconds | 15 |
| report_timeout_seconds | 60 |
| max_result_json_bytes | 5 MB |
| max_searched_types_per_call | 100 |
| max_string_length_in_response | 10000 |

Все лимиты сервер-side, клиент не может их обойти.
