# Архитектура Universal 1C MCP Server

## Общая схема

```
        +-------------------------+
        |       MCP Client        |
        | (Claude / Codex / ...) |
        +-----------+-------------+
                    | HTTPS + MCP Streamable HTTP
                    v
        +-------------------------+
        |   HTTP-сервис MCP        |  <- src/HTTPServices/MCP_HTTPService.bsl
        +-----------+-------------+
                    |
                    v
        +-------------------------+
        |   MCP_JSONRPC dispatch  |  <- routing initialize / tools/list / tools/call
        +-----------+-------------+
                    |
        +-----------v-------------+
        |   MCP_Security gate     |  <- allowlist, права, лимиты
        +-----------+-------------+
                    |
        +-----------v-------------+      +---------------+
        |   MCP_Tools dispatch    |----->| MCP_Tools_Impl|  (20 read-only tools)
        +-----------+-------------+      +-------+-------+
                    |                            |
                    v                            v
        +-----------+--------+    +--------------+-----------+
        |   MCP_Audit log    |    |   MCP_Metadata / Query / |
        +--------------------+    |   Registers / Reports /  |
                                  |   History / Values /     |
                                  |   Knowledge              |
                                  +--------------------------+
                                                |
                                                v
                                  +--------------------------+
                                  |     1С:Предприятие        |
                                  |  (БД, метаданные, СКД)   |
                                  +--------------------------+
```

## Модули

### `MCP_HTTPService`
Точка входа Streamable HTTP. Принимает POST с JSON-RPC, передаёт тело в `MCP_JSONRPC.ОбработатьЗапрос`, возвращает JSON для request-вызовов и `202 Accepted` без тела для notifications/responses. GET и DELETE возвращают `405 Method Not Allowed`, потому что сервер stateless и не открывает отдельный SSE-канал.

### `MCP_JSONRPC`
Реализует JSON-RPC 2.0 и MCP-методы:
- `initialize` — рукопожатие, возврат `protocolVersion`, `capabilities`, `serverInfo`.
- `tools/list` — список tools из `MCP_Tools`.
- `tools/call` — вызов tool, единый формат результата.
- `resources/list` / `resources/read` — статичные MCP resources (опционально).
- `ping`.

### `MCP_Tools`
Каталог всех 20 tools: описания (`name`, `title`, `description`, `inputSchema`).
Dispatcher `Выполнить(ИмяТула, Аргументы, Контекст)` → передача в реализацию.

### `MCP_Tools_Impl`
Бизнес-логика всех 20 tools. Каждая функция:
1. Валидирует аргументы.
2. Запрашивает у `MCP_Security` разрешение на тип/поле.
3. Использует `MCP_Metadata`, `MCP_Query`, `MCP_Registers`, `MCP_Reports`, `MCP_History`.
4. Кодирует результат через `MCP_Values`.
5. Возвращает структуру `{ ok, ... }`.

### `MCP_Security`
- Загрузка allowlist/denylist.
- Проверки: `ТипРазрешен(Тип)`, `ПолеРазрешено(Тип, Поле)`, `ToolРазрешен(ИмяТула, Контекст)`.
- Маскирование чувствительных полей.
- Проверка лимитов: max_limit, max_query_rows, timeouts и т.д.

### `MCP_Audit`
Запись в журнал регистрации событий `MCP.tool.<name>.success / .error` с `correlation_id`, аргументами и метаданными результата (без больших payload).

### `MCP_Values`
Кодирование значений 1С в JSON-совместимые структуры:
- Ссылка → `ObjectRef { type, uuid, presentation, navigation_url }`.
- ПеречислениеСсылка → `EnumRef`.
- Дата → ISO 8601.
- ХранилищеЗначения → метаданные без содержимого.
- Двоичные данные → пропускаются, если не разрешены.
- ТаблицаЗначений → `{ columns, rows }`.

Также реализует обратное преобразование `QueryParameterValue` → значение 1С.

### `MCP_Metadata`
- Обход всех видов метаданных (Справочники, Документы, Регистры, и т.д.).
- Поддержка `query_table`, `supports_ref`, `hierarchical`, `register_schema`.

### `MCP_Query`
- Безопасное выполнение запросов 1С.
- Валидация запроса (`validate_1c_query`): таблицы из allowlist, разрешённый список конструкций, наличие лимита, ограничение времени.
- Параметризация через `Запрос.УстановитьПараметр`.
- Возвращает `query_guidance` из `MCP_Knowledge`, если запрос содержит рискованные или сложные конструкции.

### `MCP_Knowledge`
- Встроенная база знаний для LLM по `doc/skills`: синтаксис запросов, функции, временные таблицы, составные типы, субконто и оптимизация.
- Отдаётся через tool `get_1c_query_guidance` и resources `1c://knowledge/query/*`.
- Не зависит от структуры конкретной базы: все прикладные имена должны браться через metadata tools.

### `MCP_Registers`
- Обёртки над виртуальными таблицами регистров: `СрезПервых`, `СрезПоследних`, `Остатки`, `Обороты`, `ОстаткиИОбороты`.
- Поиск движений документа: запрос к каждому разрешённому регистру с фильтром по `Регистратор`.

### `MCP_Reports`
- Список отчётов и вариантов (СКД).
- Получение параметров СКД.
- Выполнение СКД через `ПроцессорКомпоновкиДанных`.
- Адаптер для не-СКД отчётов (заглушка `supported=false`).

### `MCP_History`
- Версии объектов через подсистему версионирования (если включена).
- Журнал регистрации (`ВыгрузитьЖурналРегистрации`).
- Регистр истории статусов (для типовых конфигураций).

### `MCP_Errors`
- Стандартные коды ошибок (см. раздел 9 спецификации).
- Преобразование `ОписаниеОшибки()` в `{ code, message, details, correlation_id }`.

### `MCP_Config`
- Загрузка allowlist из константы / регистра / файла.
- Лимиты по умолчанию (см. раздел 5 спецификации).
- Runtime-настройки `MCP_ServerConfig`, включая `privacy.masked_fields` для маскирования полей перед выдачей MCP-клиенту.
- Публичная privacy-информация для LLM: активность маскирования, список полей, маски и инструкция не пытаться обходить политику.

## Поток выполнения tools/call

```
1. HTTP-сервис принимает POST на `/hs/mcp/rpc`.
2. JSON-RPC dispatcher разбирает request.
3. Проверка auth.
4. tools/call → MCP_Tools.Выполнить:
   4.1. Проверка существования tool.
   4.2. JSON Schema валидация arguments.
   4.3. Security gate: ToolРазрешен.
   4.4. Вызов реализации из MCP_Tools_Impl.
   4.5. Реализация делегирует в Metadata / Query / ... .
   4.6. Результат кодируется в JSON через MCP_Values.
   4.7. MCP_Tools добавляет privacy-информацию, если маскирование активно.
   4.8. MCP_Security маскирует поля из privacy.masked_fields.
   4.9. Audit запись по уже замаскированному результату.
   4.10. Унифицированный MCP tool result.
5. JSON-RPC dispatcher формирует response.
6. HTTP-сервис отдаёт ответ.
```

## Read-only гарантии

- В коде сервера нет операций `Записать`, `Удалить`, `Провести`, `ОтменитьПроведение`, `НачатьТранзакцию` (кроме `НачатьТранзакцию` через `Запрос` для read-only снепшотов — не применяется).
- Сервисный пользователь 1С имеет только права на чтение нужных объектов.
- Постоянные данные остаются read-only: запрещены `ИЗМЕНИТЬ`, `ДЛЯ ИЗМЕНЕНИЯ`, SQL-like `UPDATE/INSERT/DELETE/DROP` и обход прав.
- Временные таблицы разрешены внутри пакетного запроса: `ПОМЕСТИТЬ`, `ИНДЕКСИРОВАТЬ ПО`, `УНИЧТОЖИТЬ`. Они считаются рабочей областью выполнения запроса и не дают права менять прикладные данные.
- `run_1c_query` всегда применяет server-side лимит (`ПЕРВЫЕ N` / `TOP N`) и не позволяет клиенту обойти allowlist.

## Пагинация

Все списковые tools поддерживают `cursor`/`next_cursor` по схеме из `mcp_1c_metadata_pagination.md`:

- `cursor` — opaque строка (offset или Base64-JSON).
- `next_cursor = null` означает конец данных.
- Список сортируется детерминированно (например, по `ПолноеИмя`).

## Лимиты по умолчанию

| Параметр | Значение |
|---|---:|
| max_limit | 1000 |
| max_query_rows | 1000 |
| max_report_rows | 5000 |
| max_tabular_section_rows | 100 |
| max_register_rows | 1000 |
| query_timeout_seconds | 15 |
| report_timeout_seconds | 60 |
| max_result_json_bytes | 5 MB |
| max_searched_types_per_call | 100 |
| max_string_length_in_response | 10000 |

Все лимиты сервер-side, клиент не может их обойти.
